# 单机单目标实验：第一阶段

本实验对应项目记忆中的“层次一”。当前可检验的问题是：在固定红气球、已检查的 Blocks 区域，基于相机反馈的低速接近能否比固定航点更稳定地达到指定观察状态。这里的“轨迹优化”先落实为可测的闭环对照，不把已写好的视觉伺服称为训练后的优化智能体。

## 已加入的实验

- 控制对象只有 `DroneA`。`DroneB` 保持落地、无 API 控制；其位姿和速度仍被监测，移动即中止。
- `coordinate`：从统一观察点飞到固定航点，沿途取图，并在终点额外拍摄 5 帧作独立评价。
- `visual`：从同一观察点出发，以红色候选的图像偏差和 RGB 后顺序采集的深度值低速控制；失去可靠观测则停止，连续丢失、越界、碰撞或超时即中止。
- 两组共享终止评价：最近 3 帧均为已确认目标、未裁剪、采集耗时 ≤0.5 秒、框内中位表面距离 ≤2.5 米，且图像横纵最大归一化误差 ≤0.08。这个距离是气球表面的近似测距，不是目标中心的三维定位误差。
- 报告分开记录 `status`（实验安全完成并落地）和 `task_success`（达到观察目标），避免把安全落地误算成任务成功。
- 指标包括接近用时、接近路径长度、有效检测比例、全程与最后 3 帧图像偏差、最终表面距离及逐帧位置/检测/控制命令。每次运行保留配置、源码哈希、标注帧和 `report.json`；批量运行导出 `runs.csv`。

## 运行

先安装 `configs/settings.json` 并启动 Blocks，执行 `scripts/start-scene.ps1` 检查和生成气球。确认两架飞机都静止落地、API 控制释放。然后在项目根目录运行：

```powershell
& .\.venv\python.exe .\python\run_single_batch.py --repeats 1
```

一次重复包含一组坐标与视觉运行；第二组自动反转顺序。单次可用：

```powershell
& .\.venv\python.exe .\python\single_drone_experiment.py --policy visual
```

运行中任何失败会暂停仿真并保留现场；**不要直接重跑**。查看 `logs/single_*/report.json` 与飞机状态。若仅 DroneA 在空中、DroneB 在地面且仿真已暂停，检查后可运行 `python/recover_single_drone.py`；其他情况使用既有 `python/recover_airborne.py` 或人工排查。批量入口在首个失败后停止。每次正常运行后 DroneA 返回原垫、落地、解除武装、释放 API 控制；气球不会被碰撞或删除。

## 解释边界与下一批工作

本阶段使用颜色/轮廓候选和固定红气球，不支持相似实例区分或气球被遮挡后的重识别。航点、起降和安全边界使用 AirSim 真值，视觉策略只控制观察阶段；RGB 与深度不是同步采样。因此第一轮结果只能说明此固定场景的闭环表现。优先在中心目标完成成对重复，检查两种策略的成功率、时延和路径长度；随后加入目标位置扰动、短时遮挡、外观相似干扰物，并在独立测试集上评估识别与控制的耦合收益。VLX-Seek、数据集训练和 MCP 接口仍是候选研究项，须先核验模型能力、实时延迟与安全隔离，不能从本阶段结果推断其有效性。
