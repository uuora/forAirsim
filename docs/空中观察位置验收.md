# 双机空中观察位置验收

验收日期：2026-09-16。入口为项目根目录 `Validate-Air-Observation.cmd`。脚本仅在AirSim海事场景中执行双机垂直起飞、定点悬停、传感器/图像采样和降落，不执行目标接近或接触。

## 如何运行

双击：

```text
D:\forAirsim\Validate-Air-Observation.cmd
```

也可以在PowerShell运行：

```powershell
scripts\start-maritime-scene.ps1 -ShowWindow
.venv\python.exe python\validate_air_observation.py
```

运行前要求两架无人机均在甲板停稳。脚本会先采停机位基线，再让DroneA和DroneB分别飞到各自局部NED `(0, 0, -6 m)`；两机保留出生点形成的4米横向间距。实际稳定悬停高度本轮约为 `z=-5.77 m`。采样结束后先下降至甲板上方，再调用降落；考虑AirSim可能不及时更新`landed_state`，最终以“落地标志，或回到本轮起始地面高度且速度低于0.1m/s”验收。只有确认落地后才解除控制。

每轮输出到新的 `logs/air_observation_时间/`：

- `report.json`：完整结果和地面/空中对比；
- `ground/`、`air/`：各15轮六类传感器数据、6张RGB、6份DepthPlanar数组及预览；
- `position_samples.jsonl`：观察位收敛过程；
- `ground_vs_air_targets.jpg`：两机地面与空中目标可见性拼图；
- `logs/air_observation_latest.json`：最近一次输出目录。

失败时也保留目录和报告。若降落无法由标志或参考高度确认，脚本保持API控制并暂停仿真，不会在空中强制解锁；这时运行恢复流程或人工检查。

## 时间和测距解释

- 同一相机调用中的RGB与DepthPlanar时间差约3–6毫秒。
- 两机依次采集含浮点深度，空中三对RGB时间差约306–441毫秒。该数值高于先前仅RGB流程，不能把两路图像称为同步双目。
- 前视测距方向为机体正前方，摄像头另有向下5度安装角，二者不是同一条射线；不能直接用前视距离校验图像中心深度。
- 空中下视6.72米是带AirSim噪声的射线距离，与局部z变化量接近，但不能把单轮一致性写成深度精度标定。
- DepthPlanar是仿真渲染器光轴深度，不是双目模型输出，也不是实机真值。

## 下一步使用边界

该观察位可作为下一批小规模识别数据的起点。正式采集需要改变高度、横向位置、光照和遮挡，按采集会话划分训练/验证/测试。当前单一悬停点重复帧不能作为具有独立场景多样性的数据集。

下一步使用[空中多视角样本采集](空中多视角样本采集.md)中的五点采集器生成少量样本并人工复核框；在标注规则通过后，再建立现成检测模型基线。双机同步、相机标定、极线校正和立体匹配仍属后续扩展，不阻塞论文当前的轻量Agent与自适应RAG主线。

AI辅助实现与整理；本结果限于本地AirSim静态目标和本轮配置，不是实机传感器标定、识别准确率或论文创新性证明。
