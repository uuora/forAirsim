# 控制闭环与建筑场景：人工操作

2026年10月8日。实验对象为无人机：DroneA是执行无人机，DroneB是地面旁观无人机。优先推进可重复的感知—控制闭环，建筑场景作为下一阶段的静态障碍开发环境。

## 启动入口

双击 [02_识别与回放工作台.cmd](../02_识别与回放工作台.cmd)，进入“控制闭环 · 人工操作”页。原 Run-Control-Workbench.cmd 与 Run-VLX-GUI.cmd 已合并为这个中文入口，实验回放、YOLO/VLX单图验证仍可使用。

人工入口分三步：配置场景 → 预览任务 → 启动飞行。启动场景仅建立UE地面环境，不起飞；生成任务和计划也不发运动指令。停止按钮始终位于操作页底部，写入专属停止信号，控制子进程直接读取并开始清零/停稳核查；随后由运行器落地、释放。该入口不是硬实时急停，启动或RPC阻塞期间仍可能需要等待。

## 首先验证基础闭环

1. 关闭本工具已安全结束的场景；保留其他占用AirSim端口的实验。
2. 选择“基础闭环 · 独立UE会话”和“零门控 · 8秒”，点击“生成并检查本次计划”。
3. 查看本次计划路径，点击“启动本次闭环飞行”。基础验证会建立独立UE会话，结束后仅在落地、释放、暂停及新鲜地面核查通过时关闭所属UE。
4. 零门控通过后进行160秒运动先导，再用新UE会话进行相同条件独立重复。缺槽、未知端点、停止失败等仍计入未通过。
5. 100毫米验证与正式轨迹方法比较继续按阶段准入；本人工界面暂不提供100毫米快捷按钮。

当前控制仍采用固定世界高度NED −3米、XY指令上限0.03米/秒、0.12秒目标租约。YOLO候选、低频VLX复核、属性判据和持续关联在父进程，自状态控制、目标指令时效检查和实际清零在独立Windows spawn子进程。失去当前目标证据时停止目标动作，不能由自然语言输入取消这些限制。

“运行器完成”和“独立验收通过”分别保存：独立分析重新检查配置与源码快照、图像和深度文件、目标身份、实际控制事件、停稳采样、位移及测量槽完整性。缺槽或位移不够仍未通过，即使运行器已正常落地收尾。当前都是开发验证，不用于宣称算法优于其他方法。

## 新建筑场景

默认 [t1_building_scene_v2.json](../configs/t1_building_scene_v2.json) 含白条目标气球、普通红色干扰气球及三栋静态建筑，基于已有Blocks工程在新UE会话中生成，不修改已有地图资源。建筑使用有位置/尺度读回的静态立方体网格和立面纹理。另有[转角短程场景](../configs/t1_building_corner_scene_v2.json)，用于在既定低速时长内验证绕开建筑净空边界的完整短路径；它不等同于默认场景的米级路线。

配置单位均为世界NED米：X向前、Y向右、Z向下；高度3米对应Z=−3。可以复制JSON后调整建筑`center_ned_m`、`size_m`、观察点`observation_goal_ned_m`和工作空间。当前仅支持轴对齐静态建筑；起降柱、起点和观察点不得进入建筑净空范围。人工入口的`clearance_m`至少为0.75米，并单独检查观察点的垂直降落柱。位置、尺寸与路径会在启动前检查，配置有变化需要重启场景。旧0.35米场景和未通过的转角试次继续保留。

1. 选择场景JSON，刷新俯视地图。灰块为建筑，外虚框为净空，蓝虚线为静态规划，绿线为运行期间自状态采样轨迹。
2. 点击“启动建筑场景（地面）”，等待场景就绪。
3. 输入“靠近带白色横条的红色气球，保持3米高度，避开建筑物”，生成任务预览。
4. 将验证模式改为“新建筑场景 · 低速短验证”，生成计划，再单独点击飞行按钮。先做零门控，再做低速运动验证；每次飞行后查看报告、安全关闭并启动新场景进行独立重复。
5. 已结束的建筑UE保留供人工查看，点击“安全关闭场景”才关闭。地面和释放核查不通过时保留进程，不强行终止控制。

重新打开界面后，可点击“载入已有场景会话”，选择该场景日志目录的`scene_session.json`。程序核对UE进程身份后恢复查看和安全关闭入口；已消费的飞行计划需要重新建立场景，不会自动重复起飞。

绕行规划采用已配置的建筑包围盒、净空膨胀和可见图最短路径。子进程在发非零目标或反馈指令前检查当前位置到预测位置的线段，并检查建筑碰撞记录；目标身份、图像时效、自状态时效、速度和停止约束仍同时有效。当前这是**已知静态地图的开发避障**，不等于YOLO识别建筑、未知障碍重建、动态避障或已经完成全程绕行。新场景的运动幅度扩大需要独立实测，基础50毫米通过也不能直接证明新场景通过。

论文场景示意可使用[矢量SVG](../reports/t1_building_scene_20261008/configured_scene.svg)或[PDF](../reports/t1_building_scene_20261008/configured_scene.pdf)，路径点[CSV](../reports/t1_building_scene_20261008/route_waypoints.csv)和建筑坐标[CSV](../reports/t1_building_scene_20261008/building_geometry.csv)可导入Origin。该图展示配置几何和规划路径，不能标注为实测飞行轨迹或避障成功结果。

## LLM输入接口

当前无新增LLM服务接入；输入框使用本地受约束解析，生成如下任务协议：

```json
{
  "schema_version": 1,
  "kind": "T1_OBSERVE_TARGET",
  "scene_id": "t1_building_courtyard_v1",
  "target_description": "带白色横条的红色气球",
  "observation_goal_ned_m": [3.0, -1.8, -3.0],
  "fixed_height_ned_m": -3.0,
  "avoid_buildings": true,
  "speed_cap_m_s": 0.03,
  "execution_state": "PREVIEW_ONLY",
  "flight_authorized": false
}
```

将来LLM只负责把语言转换为经检查的目标与约束任务，经过界面预览和独立启动，再交给规划/控制模块。它不直接生成或执行Python、RPC、速度指令或取消避障。当前仅支持固定白条目标及3米高度，其他对象/高度输入会拒绝，不将任意文本视为已经完成的自由语言指令理解。
