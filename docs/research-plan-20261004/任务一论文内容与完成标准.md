## 1. 任务一究竟研究什么

一架无人机持续观察一个**预先指定的气球实例**。场景可以放置相似气球作为干扰物，任务目标仍只有一个。目标是否在画面内、检测是否有框、系统是否仍跟踪指定实例，分别评价。暂以静止目标开始，移动目标作为通过基础条件后的扩展，不把双机、碰撞刷新或实机迁移加入本章。[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=67–68、204、212、228`；[现有正式采数准入](../research-plan-20261003/T1正式采数准入与后续路线.md)

拟回答三个有对应实验的问题：

- **RQ1 观测表达：**图像检测、时序关联与低频语义复核能否形成有时效和拒识条件的指定目标状态？需要身份标注、拒识记录和响应时序验证。
- **RQ2 规划作用：**在同一检测后端、候选轨迹、运动约束和资源预算下，加入视场与身份状态是否改善有效观测及失锁恢复？需要四基线、全部开始回合和全部评价时刻统计。
- **RQ3 代价与限制：**这些改善是否伴随航程、平滑性、计算/API 开销或等待时间的增加，在遮挡、干扰、延迟下如何退化？需要失败和代价结果，不能只展示成功轨迹。

这里的研究贡献候选是“观测评价如何改变轨迹选择与恢复行为”。YOLO、VLX、AirSim、PyQt5 的接入属于支撑实现；仅完成 API 调用或界面显示，还不能支持上述方法效果。[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=68、191、195、212`

## 3. 方法部分必须明确的变量与假设

以下是拟写的模型接口，须与最后冻结的源码逐项对应；不是已完成算法的结果描述。[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=68、143、188`；[时间戳观测接口](../../python/timestamped_target_provider.py)、[已有规划器](../../python/perception_trajectory_planner.py)

| 符号 | 含义与限制 |
|---|---|
| \(x_t=(p_t,v_t,a_t,q_t)\) | 无人机自身查询状态；位置所在原点与坐标系必须标明 |
| \(I_k,D_k,K,T^W_{C,k}\) | RGB、深度、Scene 内参、图像响应对应的相机变换；查询/读回时间不称曝光时间 |
| \(b_{k,j},s^{det}_{k,j},\ell_{k,j}\) | 候选框、检测原始分数与类别；检测分数不等于指定实例身份概率 |
| \(\hat p^{surf}_{k,j}\) | RGB/深度估计的代表可见表面点；不称真实气球中心 |
| \(r_{k,j},g_k\) | 本地轨迹关联号、目标任务版本；关联号不等于评分真值身份 |
| \(e^{id}_k\) | 来自时序与语义复核的身份依据分数／状态；只有经独立验证校准后才命名为概率 |
| \(Q^{vis}_k,A_k\) | 图像可见质量与明确口径的观测年龄；预测质量与实测评分分别保留 |
| \(\xi_i(\tau)\) | 候选轨迹，含时间域、位置、速度及求解状态 |
| \(u_t\) | 实际发送的控制请求，和参考轨迹及实际响应分别记录 |

拟用共同可行候选集表达规划：

\[
\xi_t^* = \arg\min_{\xi_i\in\mathcal F_t}
\left[w_d J_d(\xi_i)+w_m J_m(\xi_i)+w_v J_{vis}(\xi_i;z_t)
 +w_{id}J_{id}(\xi_i;z_t)\right].
\]

\(\mathcal F_t\) 由共同工作区、运动、障碍和执行预算约束筛选；求解无可行候选、观测过期、身份不确定分别有明确处置。\(J_{id}\) 首版可以表达“身份不确定时保持/重观测的动作代价及门槛”，须写清其依据；没有未来视点身份预测器时，不写成“预测未来身份概率”。VLX 首版也不逐条评价未来候选视图。不同质量量纲需要声明归一化方式，权重只能由开发集选取并在正式测试前冻结。[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=68、186、195`；[现有质量参考的语义](../research-plan-20261003/V6.2居中参考与空间门槛实测结果.md)

感知链和独立评分链分别保留：控制器只能读取图像、深度、自身状态及由其产生的估计。目标 actor 真值、实例 ID、无遮挡参考图和遮挡掩膜用于布置场景或评分，不作为控制器目标位置或身份输入。相机投影计算的往返一致性只支持该几何契约的内部一致性，仍需实际图像锚点验证。[三维接口验收计划](../research-plan-20261003/下一轮三维与姿态接口验收计划.md)、[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=188、228`

## 4. YOLO 和 VLX 在本章中的具体角色

### 4.1 YOLO：高频候选检测

保留颜色/轮廓作为易复算后端基线，主方法比较拟统一采用已冻结的 YOLO 后端。已有 YOLO11n 探测将 COCO `sports ball` 类映射为气球候选，尚不能称“气球专用训练模型”；旧六帧中有四帧产生候选，也不能解释为 66.7% 检测准确率。需要记录权重哈希、模型/推理版本、分辨率、device、阈值、NMS、最大候选数和预热。候选覆盖、误检、框误差与实例关联分别按独立标注评估。[接入决策](../YOLO与VLX接入决策_20260930.md)、[原探测报告](../../logs/phase1_perception_probe_20260930_113827/report.json)、[探测实现](../../python/benchmark_phase1_perception.py)

按场景或独立回合拆分训练/开发/测试数据，不能把相邻帧随机分成训练与测试。先用现有公开模型做基线；若气球覆盖不足，使用 AirSim 图像的独立标注进行轻量适配。没有实际训练日志、拆分清单和未参与调整的测试评估时，不写“已微调”。用户已将范围限定为 AirSim，本阶段不要求实机或现实拍摄数据。[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=68、195`；[任务登记](../../configs/thesis_simulation_tasks.json)

### 4.2 VLX：低频指定目标复核

使用用户已配置的 VLX API，拟在初始化、关联歧义、质量持续下降及遮挡重现时触发。当前云客户端实际能力须按源码和运行回执命名：现有图像＋文字请求不能自动称为“服务器对 YOLO 候选排序”。若返回框在本地与 YOLO 候选关联，记录为**VLX 图文定位＋本地候选关联**。只有真实传输外部框且有回执证明时，才写外部 proposal ranking。[接入决策](../YOLO与VLX接入决策_20260930.md)、[云客户端](../../python/vlx_api_client.py)、[离线探测](../../python/vlx_seek_probe.py)

异步请求需绑定原图哈希、frame_id、任务版本、文字描述版本和请求/返回时间。多候选不唯一、空响应、超时、任务版本变化、旧帧结果过期均返回不确定状态；慢响应须在新帧上重新关联或重新确认。复核等待、失败与 API 调用次数计入本回合代价。VLX 输出仅用于身份依据和有限任务状态，不直接生成速度、航点或调用飞控。[接入决策](../YOLO与VLX接入决策_20260930.md)、[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=68、195`

## 5. 四基线与两组必要消融

以下是拟冻结定义。现有 V6.2 只做了居中权重 0/4 的效率—感知开发比较，没有完成下面四方法正式比较。[V6.2 结果](../research-plan-20261003/V6.2居中参考与空间门槛实测结果.md)、[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=186`

| 方法 | 使用的信息／规划行为 | 比较目的 |
|---|---|---|
| B0 固定跟随 | 用初始化的观测估计确定固定观察点/跟随偏置，不随质量重新排名；不能用目标真值指定观察点 | 完整闭环相对固定策略的收益 |
| B1 距离规划 | 用新鲜共同观测更新，按共同距离/运动代价从共同候选中选取；身份质量和视场代价关闭 | 检验质量评价的增量 |
| B2 可见性规划 | 在 B1 上加入同一可见性/居中代价；不由语义身份状态改变轨迹或恢复策略 | 将几何可见作用与指定实例作用分开 |
| B3 身份核验与轨迹规划联合闭环 | 在 B2 上加入时序身份依据、VLX 有限复核及由该状态触发的保持/重观测；所有动作仍过共同安全执行器 | 检验身份状态进入规划/恢复的增量 |

B1–B3 共享新鲜图像输入接口、YOLO 权重、关联实现、候选生成、约束、执行器、场景序列、运行设备及运行预算，只改变登记的方法因素。B0 使用同一感知输入与安全执行器，但其固定决策定义决定它不作质量重排名；它不是“仅改变一个代价权重”的消融。共享代码与候选不代表不同闭环轨迹能获取完全相同图像：端到端比较让视点随策略变化，检测模块评估另用相同保存帧回放。所有方法等待、超时和保护计入开销。[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=186、188`；[现有准入](../research-plan-20261003/T1正式采数准入与后续路线.md)

必要消融单独进行，避免把后端变化解释为规划收益：

1. **检测后端消融：**固定 B2 或 B3 的其余实现，颜色/轮廓与 YOLO 互换；报告候选覆盖、误检、端到端指标和耗时。必要时补 VLX 单独图文定位回放，用于能力和延迟分析，不默认是可用高频控制后端。
2. **低频复核消融：**固定 B3、YOLO、时序关联和质量代价，仅关闭/打开 VLX 复核；无复核组仍保留相同拒识、安全与计算/API 等待预算口径。若做分数校准，再增加“未校准/校准”的单因素条件；没有独立校准集时不安排虚假的校准结果。

四基线回答系统差别，消融回答具体因素作用。有效性不以“YOLO 比颜色更先进”或“用了大模型”推定，需要指定目标与任务指标结果。[接入决策](../YOLO与VLX接入决策_20260930.md)、[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=186、195、228`

## 7. 指标、字段与论文图表

### 7.1 主指标与完整分母

在预先登记的全部评价时刻 \(\mathcal T\) 上，身份保持率拟定义为

\[
R_{id}=\frac{\sum_{t\in\mathcal T}\mathbf1[\hat y_t=y^*]}{|\mathcal T|}.
\]

未输出、关联错误与系统失锁均计为失败；遮挡期间不能因没有检测就把时刻从分母删除。采用冻结的固定评价时间网格，避免方法改变输出频率就改变分母。真值不可用的时刻另外报告评分覆盖与缺失原因，不悄悄补成正确。若辅助报告“可见条件下正确率”，分母只能来自独立真值可见条件，并同时保留主指标。[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=143、188、228`

回合成功率按所有确认开始任务的回合计算；成功需同时满足指定实例正确、预定连续有效观测及安全约束。超时、未重获、无可行解计入失败；结束后的落地释放单独验收。有效可见率、最长失锁、重获时间、身份切换和错误目标接近次数须有独立实例关联和可见性评分。未恢复回合不能只从“平均重获时间”中删除，报告未恢复比例及任务时窗截尾。[开题提取](../research-plan-20260930/source/proposal_extract.json)：`body_index=188、228`
