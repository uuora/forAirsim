## 1. 当前接口与已经核验的空间输出

新表面接口接收当前RGB帧、持续选择证书、配对DepthPerspective及两类响应的实际相机位姿。它核对会话、目标版本、图像哈希、描述、选中框内容、确认帧数量和复核期限。没有当前指定实例输出时，深度不能单独生成供目标规划使用的表面；actor位置与分割信息只在场景构造和独立评价中使用。[表面接口](D:/forAirsim/python/t1_candidate_surface_v2.py)

代表表面由框内有效深度中的一个实际像素回投得到；RGB框中心视线在代表表面的轴向深度平面上形成居中参考。四个框角构成同深度平面的支持区域，随后按响应四元数旋转和记录的局部至世界平移转换。表面、居中参考与支持区域分别保存，它们均不提供气球物理中心位置。[实际姿态几何](D:/forAirsim/python/t1_pose_geometry.py)

回放采用上一批四个地面UE会话，全部保存帧进入分析。结果见[回放汇总](D:/forAirsim/logs/t1_temporal_surface_replay_20261004/summary.json)。

## 2. 新机载闭环如何连接

机载链依次进行专用YOLO候选检测、VLX低频复核、持续身份关联、配对表面估计和姿态候选规划。规划器保存当前相机朝向，以固定高度XY平移预览候选视点，评价RGB居中、射线距离与加速度平方均值。候选可行性按离散采样检查，当前框的深度平面不能预测未来遮挡。[观察器](D:/forAirsim/python/t1_flight_observer.py)、[姿态规划器](D:/forAirsim/python/t1_pose_trajectory_planner.py)

动作准入要求当前身份与表面均有效、自状态新鲜，并满足时效和运动边界。一个目标帧只准入一次目标相关请求；新的当前帧才能提出下一次请求。短请求到期后，执行器显式清除目标相关速度并查询实际停止过程，再进入阻塞图像采集、模型推理或媒体保存。AirSim请求持续时间记录的是计划动作预算，自动停车行为需要独立证据，当前实现依靠明确的自状态停止流程。[动作策略](D:/forAirsim/python/t1_identity_motion_policy.py)、[执行与停止记录](D:/forAirsim/python/t1_identity_flight.py)

失锁时停止目标相关动作并保持高度，等待新的属性复核与帧确认。起飞和定高建立采用独立生命周期控制，低速研究段在状态稳定后开始，落地与释放控制另存终态。研究段XY请求幅度、实际速度峰值、制动响应与起降运动分别汇总。[飞行程序](D:/forAirsim/python/t1_identity_flight.py)

## 4. 已发生的机载首试失败与修复

首轮零目标速度尝试实际执行了起飞，保存20帧RGB、20份深度和20帧分割，共60份媒体。最终报告包含未转为Python标量的NumPy整型，JSON保存报错；磁盘上的报告停留在初始`RUNNING`状态。原启动清单记`FAIL`，其完整身份、表面和动作统计缺失，媒体数量不能替代这些结果。[原始清单](D:/forAirsim/logs/t1_identity_flight_zero_v1_20261004/manifest.json)、[序列化异常](D:/forAirsim/logs/t1_identity_flight_zero_v1_20261004/runner.stderr.log)

落地确认另有异步状态问题。首版在停桨前等待 landed 标志，载机已经接触地面但 API 控制尚未释放。补充恢复在地面接触和连续静止证据后执行停桨与控制释放；首次新查询的 landed 标志仍未更新，恢复回执保留失败。第二次新回执确认两机落地、静止且控制释放，随后经进程号、路径和 UTC 启动时间核对完成关闭。补充结束回执保存为成功，原启动清单的失败状态不改。[首次恢复](D:/forAirsim/logs/t1_identity_flight_zero_v1_20261004/supplemental_ground_recovery.json)、[第二次恢复](D:/forAirsim/logs/t1_identity_flight_zero_v1_20261004/supplemental_ground_recovery_v2.json)、[关闭回执](D:/forAirsim/logs/t1_identity_flight_zero_v1_20261004/supplemental_owned_closure.json)

修正版将NumPy标量显式转换为Python标量，保留有限数值检查；落地按地面接触、采样静止、停桨、释放控制和 landed 更新的顺序确认。阻塞采集与推理前，所有零速度及制动请求都需保存实际采样停稳。修复进入新的源码与配置快照，后续独立分析用于核对修正版运行，首试失败继续计入开发尝试。[修正版执行实现](D:/forAirsim/python/t1_identity_flight.py)

第二轮`zero_v1p1`完整保存20帧、60份媒体和终态报告，表面接口接受16帧。落地确认窗口在`landAsync`返回后只再等8秒，仍有下降过程未结束，故报告保留`LANDING_RECOVERY_RuntimeError`失败。补充恢复随后以独立接地、连续静止证据完成控制释放、暂停和本次UE进程关闭。第二轮报告保存完成后的stdout汇总还有NumPy计数标量错误；它与首轮终态写盘失败具有不同影响，第二轮已封存报告和逐帧记录不回写。[第二轮终态](D:/forAirsim/logs/t1_identity_flight_zero_v1p1_20261004/flight/report.json)、[stdout错误](D:/forAirsim/logs/t1_identity_flight_zero_v1p1_20261004/runner.stderr.log)、[补充恢复](D:/forAirsim/logs/t1_identity_flight_zero_v1p1_20261004/supplemental_ground_recovery.json)、[补充关闭](D:/forAirsim/logs/t1_identity_flight_zero_v1p1_20261004/supplemental_owned_closure.json)

新版本将落地确认窗口设为45秒，控制台输出也采用有限标量转换和明确的布尔计数。每轮模型、配置与源码分别留存。工程启动与收尾失败单列，完整或缺失的身份结果按实际证据记录，不能将工程故障合并为模型选错目标。[当前修复](D:/forAirsim/python/t1_identity_flight.py)

短XY版本`short_v1p2`有完整41帧和终态报告。序号4、12、28、36形成表面，四帧都从18个候选中得到`POSE_TRAJECTORY_SELECTED`。规划后的前次请求间隔分别为0.562、0.516、0.468和0.562秒，动作门控均以`PREVIOUS_COMMAND_INTERVAL_EXCEEDED`拒绝，目标相关非零动作数为0。终态保留`NO_VALID_INTEGRATION_OUTPUT`失败；两机落地、控制释放、暂停和 owned UE关闭已分别通过新回执核对。[完整短XY报告](D:/forAirsim/logs/t1_identity_flight_short_v1p2_20261004/flight/report.json)、[逐帧记录](D:/forAirsim/logs/t1_identity_flight_short_v1p2_20261004/flight/frame_results.jsonl)、[安全结束清单](D:/forAirsim/logs/t1_identity_flight_short_v1p2_20261004/manifest.json)

本轮负结果发生在规划输出至实际动作准入之间。目标相关动作未执行，因而不能据此评价轨迹改善或运动中的恢复。随后采用批量计算候选投影，保持18个候选、采样间隔、代价和身份时效阈值；数学等价性与新会话时序分别核验。独立分析区分计算延迟导致的关联断链、无身份输出和实际选错目标。[姿态候选实现](D:/forAirsim/python/t1_pose_trajectory_planner.py)

批量投影已完成保存数据核对。四个有效帧的18候选几何与居中代价记录差为0；同一保存帧几何的20轮成对测量按奇偶轮交换执行先后次序，逐点版本中位211.449毫秒，批量版本6.296毫秒，局部耗时比为33.586。该比值只描述投影数学计算，不表示机载整帧、网络或控制加速；新飞行的按时完成数量另外登记。[局部投影测量回执](D:/forAirsim/logs/t1_pose_projection_batch_profile_20261004/receipt.json)

最终独立分析核对各轮开始、时隙、身份输出、命令和结束状态。`zero_v1p2`通过开发证据门，20帧中16帧身份正确、4帧无输出，16个表面输出对应零目标速度请求；它验证该设置下的接口，不评价轨迹改善。`short_v1p2`的41帧中4帧身份正确、37帧无输出，保存231个自状态零速度请求。观察器本身晚到1帧，实际动作门控决策36帧按时、5帧晚到，包含停止流程的整帧完成晚到10帧。返回后观察器在2.188秒出现正确身份，包含规划与停止的整帧完成延迟为2.516秒，随后又失锁。因此，该版本的持续关联和运动闭环未达到本次准入目标。[最终独立分析](D:/forAirsim/logs/t1_identity_flight_analysis_final_20261005/report.json)

已保存自状态查询的最大间隙在`zero_v1p2`为0.547秒、`short_v1p2`为0.578秒。0.05秒是协议的监测预算，不能据此声称实际达到固定50毫秒周期；未保存的中间查询也不补入分析。起飞、稳定建立和落地均与上述低速研究段分列。[分段统计与范围](D:/forAirsim/logs/t1_identity_flight_analysis_final_20261005/summary.md)
