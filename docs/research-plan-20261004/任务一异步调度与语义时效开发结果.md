# 任务一异步调度与语义时效开发结果

更新日期：2026-10-05。研究范围仍为AirSim中的单机、一个指定气球及相似干扰目标。

## 1. 本轮实现

控制线程独占自身状态查询、当前帧动作准入、短指令派发、到期清零和采样停止。感知主线程负责配对图像、YOLO、低频VLX、当前表面与候选规划；每次提交完整的当前帧证书，最终动作准入重新采用控制线程读取的自状态。两个线程分别创建和使用各自的RPC客户端。控制线程退出后，生命周期流程才接管着陆。[新运行器](D:/forAirsim/python/t1_identity_flight_v2.py)、[独立控制器](D:/forAirsim/python/t1_async_control.py)

保留当前图像年龄0.5秒、自状态年龄0.12秒、指令租约不超过0.12秒、XY请求上限0.03 m/s和原工作空间。一个目标帧至多用于一次目标指令。配置50毫秒状态查询周期，同时保存实际间隔。记录使用有限内存缓冲，单一主线程写文件；RPC回调单列返回结果。最终账本写入位于着陆恢复之后，记录失败不会成为跳过着陆的理由。[动作准入](D:/forAirsim/python/t1_identity_motion_policy.py)、[新版本冻结协议](D:/forAirsim/python/prepare_t1_identity_flight_v2.py)

## 3. 调度测量与阻塞实验

修正传输配置后的三次试验，保存SELF_STATE间隔中位数均约47毫秒，P95约63毫秒，最大分别为78、94、78毫秒；记录中没有超过120毫秒的相邻SELF_STATE间隔。它们包含较多零保持查询，尚未覆盖非零目标运动。[实际间隔](D:/forAirsim/logs/t1_async_timing_final_v2_20261005/summary.md)

阻塞试次在时隙14的控制决策后、媒体保存前，以及时隙26的图像采集后、观察器处理前，各预声明暂停主线程0.65秒。实际持续0.656和0.657秒，期间分别保存15、14个自状态读回；触及阻塞区间的最大读回间隔均为63毫秒，保存自身零指令分别16、14次。过期帧继续通过原时效条件拒绝目标动作。两段均没有活动的非零目标租约，因此本轮证明的是感知阻塞期间零保持与状态查询继续进行，非零目标指令在阻塞期间的到期清除仍待实飞验证。[逐段阻塞记录](D:/forAirsim/logs/t1_async_timing_final_v2_20261005/report.json)

![保存自状态查询间隔及两处阻塞区间](D:/forAirsim/logs/t1_async_timing_final_v2_20261005/self_state_receipt_cadence.png)

旧版短飞行相邻SELF_STATE事件间隔最大328毫秒、P95为250毫秒；500毫秒来自阶段起点到首个保存查询读回的阶段头部间隙，也出现在包含阶段边界的合并统计中。两种统计覆盖不同。旧试次含24次非零目标指令，本轮没有非零目标指令，而且试次按时间先后开发，不能把这组记录当作匹配条件下的方法收益对照。[旧版与新版分列复算](D:/forAirsim/logs/t1_async_timing_final_v2_20261005/report.json)

正常短试次的实际门控40个及时、1个晚到，完整帧完成39个及时、2个晚到；阻塞试次的门控38个及时、1个晚到、2个未知，完整完成34个及时、5个晚到、2个未知。这些动作均保持零输出，不能据此认定有目标运动时完整0.4秒周期已达成。[分事件时钟](D:/forAirsim/logs/t1_async_timing_final_v2_20261005/report.json)

## 4. 本轮负结果的定位

首轮控制传输故障与后续感知无输出分开处理。msgpack RPC的超时检查按较粗的时钟递减；设置小于1秒的值可能在下一次检查时使新请求过期。控制客户端改为2秒传输设置，观测、动作和自状态的准入期限保留原值。传输超时设置不能充当动作租约保险。[当前运行器与回调](D:/forAirsim/python/t1_identity_flight_v2.py)

后续YOLO仍产生当前候选，VLX请求也有HTTP返回，但请求返回不等于通过当前证书的时效与确认条件。正常短试次保存5次语义提交，语义轮询没有获得有效当前证书；零速度试次第三次复核在末帧成为有效语义证据，随后缺少较新确认帧。迟到证据未用于维持目标动作。[原始正常短报告](D:/forAirsim/logs/t1_identity_async_short_v2p1_20261005/flight/report.json)、[原始零速度报告](D:/forAirsim/logs/t1_identity_async_zero_v2p1_20261005/flight/report.json)

四次仿真关闭后，另对同一保存RGB做3次顺序请求诊断。YOLO每次检出2个候选，准备耗时31、47、31毫秒；VLX三次均为READ_TIMEOUT，请求耗时3.078、3.094、3.063秒，没有收到推理回复，返回框和回复绑定保持未知。这说明当时未在当前3秒传输期限内收到回复，不能据此判定鉴权失败或服务整体不可用。诊断没有飞行，3次额外提交与飞行试次分别计数，原2秒语义策略预算未改。[组件诊断与封存](D:/forAirsim/logs/t1_vlx_latency_diagnostic_20261005/summary.md)
