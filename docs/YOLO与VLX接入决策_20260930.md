# 第一阶段 YOLO 与 VLX 接入决策

## 当前建议

继续以单机单目标完成位置变化对照，保留颜色/轮廓方法作为简单基线。YOLO 加入感知对照；VLX 加入低频语义确认实验。是否做完整 agent，取决于它是否在目标选择或恢复决策上产生可验证的收益。

本轮已新增未标注 RGB 原图和哈希记录，离线检测/响应延迟探测使用这些原图。在线飞行仍使用原有 RGB/深度策略。模型回放输出不计为在线飞行结果。

## 本轮实际结果与接入选择

位置变化先导已完成：三次独立 Unreal 进程、12 次安全收尾、374 张未标注 RGB。中心条件两策略各 2/2 达标；Y=-0.6 m 与 Y=+0.6 m 两个条件下，固定航点各 0/2、视觉闭环各 2/2。每条件只有一次会话，仍需重复以排除会话因素。[位置先导汇总](../logs/phase1_lateral_sweep_20260930_112257_1344693/analysis/summary.md)。

六帧探测实际调用已完成，全部三种方法均返回；“返回”不等于定位正确。YOLO 在四帧产生气球候选，另外两帧没有气球候选。VLX 六次均返回一个有效几何框，尚无独立人工定位评分。[探测报告](../logs/phase1_perception_probe_20260930_113827/report.json)、[耗时汇总](../logs/phase1_perception_probe_20260930_113827/summary.md)。

| 方法 | 六次调用中位数 | 首次调用 | 后五次中位数 | 处理耗时 ≤0.5 s |
|---|---:|---:|---:|---:|
| 颜色/轮廓 | 2.56 ms | 2.4 ms | 2.7 ms | 6/6 |
| YOLO11n（CPU） | 57.37 ms | 11.65 s | 55.9 ms | 5/6 |
| 云端 VLX 图像＋文字 | 0.869 s | 1.293 s | 0.813 s | 0/6 |

YOLO 首次调用包含初始化开销；正式在线接入需要在起飞前完成预热并确认就绪。现有预训练权重的候选覆盖仍需核验，不能直接替换当前闭环检测器。云端 VLX 本次调用全部超过 0.5 s 观测年龄门槛，因此当前选用“低频确认、局部跟踪与新帧复核”的接入方向；这个判断仅对应本次配置和小样本耗时。完整 agent 的实现安排在目标选择收益和过期处理验证之后。

## 推荐分工

| 模块 | 职责 | 接入条件 |
|---|---|---|
| 颜色/轮廓 | 简单检测与既有视觉闭环基线 | 保留原协议和失败记录 |
| YOLO | 图像检测框、类别、分数 | 气球检测覆盖、错误类型和整链延迟经过独立标注验证 |
| VLX | 根据文字确认目标；候选歧义或跟踪丢失时进行低频确认 | 单独测量选择收益、响应时延与过期比例 |
| 确定性状态机 | 对准、接近、悬停、恢复、返航和降落 | 输入必须通过时效、身份与几何检查 |

官方 YOLO 接口提供检测框、类别/分数以及推理阶段耗时；本项目还测量 Python 调用墙钟耗时，不能只用模型推理时间代替整链延迟。[Ultralytics 检测文档](https://docs.ultralytics.com/tasks/detect)、[预测文档](https://docs.ultralytics.com/modes/predict)。

官方 VLX-Seek 1.5-10B 本地接口可以接收外部原图像素候选框；当前项目云端 3B 请求发送图像与文字。两种接口分别记录。此次离线探测将 YOLO 与云端 VLX 作为两个独立条件；服务端没有接收 YOLO 框的证据时，结果名称使用“VLX 图像＋文字”。[官方推理指南](https://github.com/om-ai-lab/VLX-Seek/blob/main/docs/inference.md)。

## 第一轮探测协议

1. 使用中心、Y=-0.6 m、Y=+0.6 m 三个预设条件，固定航点不随目标修改。各条件重启一次 Unreal，各跑两对试次；属于开发先导。
2. 固定抽取每个条件第一场坐标试次的首、末原始 RGB，共六帧。先定义采样，再查看模型结果；同飞行内图像相关。
3. 同图分别运行颜色、预训练 YOLO11n 和云端 VLX。YOLO 使用 CPU、640 输入、0.25 阈值；记录权重哈希和首次加载耗时。`sports ball→balloon` 只是当前 COCO 类别映射，尚无专用气球训练。
4. VLX 使用“红色气球”、中文模板、temperature=0；单次请求超时 30 s、最多一次尝试。保存返回框与选择状态；空框、多框、越界框与调用错误全部保留。
5. 报告墙钟中位数/P95、错误和 ≤0.5 s 处理预算计数。六帧仅用于工程探测，不能代表部署的延迟分布；离线耗时不含采集、排队或目标运动。
6. 未完成独立人工真值，不报告准确率。具备原图和模型输出以后，再由实际复核者评估检测与实例选择。

入口：`python/benchmark_phase1_perception.py --sweep <完成的清单> --output <新目录> --run-vlx`。原始日志保持不覆盖。

## 何时构建 VLX agent

先完成上述探测和人工核验。若低频确认能减少误选，并且代价可接受，再实现一个有限职责的确认组件：输入原图、frame_id、采集时间、描述；输出框/实例引用、原始模型结果、确认状态和耗时。

确认组件采用异步请求，限制同时在途数量，记录超时；过期、几何无效、身份不明或多框结果返回“不确定”，由状态机悬停或恢复。当前闭环使用 0.5 s 观测年龄门槛，慢响应应在受控悬停后用新帧重新验证目标。其输出不给出速度或航点，也不直接调用飞控。

完整实验需分别比较颜色、YOLO、VLX 图像＋文字以及语义确认策略；只有外部候选框传输成立，才新增 YOLO 候选→VLX 的组合条件。接入后的主张以真实闭环试次和完整分母为准。

AI 使用说明：接口检查、探测脚本和接入设计由 AI 辅助完成；模型准确率与实验结论仍需对应实际运行和人工真值。
