## 4. 接下来需要实现的功能及验收

| 顺序 | 待实现/完善功能 | 验收场景 |
|---|---|---|
| P0 | 完整运行台账与统一模式标记；登记目标真值/机体真值/相机/接触反馈的访问；保存当前基线 | 成功、失败、中断、参数拒绝都可解释；视觉与坐标兜底分开计数；版本/配置/种子可追溯 |
| P1 | 限定区域内未知位置的单静态气球获取；固定目标坐标仅供评测，准备航点允许使用预定义区域 | 目标在多个位置与初始视角；起始不在视野内能有限搜索；无目标时正常超时终止 |
| P2 | 可替换感知接口，支持现有颜色及轻量YOLO/YOLO-seg；采集时间、有效性与来源字段 | 同图像对照检出、误检、裁剪、深度缺失、陈旧观测；SAM仅离线标注，不强制在线 |
| P3 | 将视觉接近入口参数化并覆盖偏移位置，保留有界执行和故障退出；统一RGB/深度时间匹配 | 换位置后仍可接近；缺帧/旧帧/无效深度时不使用无效观测推进；分别统计视觉完成和坐标兜底 |
| P4（研究重点） | 已加入独立 `ContactAttemptAssessment` 和 `run_visual_fallback.py --attempt-mode observation` 入口；根据观测区分暂失、待确认、未完成、完成，默认故障注入仍保留作基线 | 短遮挡不立即误判；长期丢失触发有界接替资格；无新接触不计完成；下一步在AirSim中验证真实未完成、恢复与接替 |
| P5（研究重点） | 在本机恢复与B接替之间选择；通道清空与双机互斥；两机均失败终止 | A已完成不派B；A可恢复时按策略处理；需要B时接替；B超时保留原因并结束；无重复执行 |
| P6 | 场景与故障矩阵：位置、视角、遮挡、相似颜色干扰、深度缺失与延迟；可复现随机种子 | 场景可复跑；自然遮挡与人为故障注入区分；全部策略条件一致 |
| P7 | 正式算法对照/消融与统计报告 | 比较固定超时、连续丢失阈值、本机重试、所提方法；相同双机资源；报告失败和置信区间 |
| P8（非阻塞扩展） | LLM低频任务解析到固定schema | 合法任务、缺参、非法范围、无关输入；解析与飞行状态机隔离；不影响主算法评估 |

P1–P5先用现有颜色检测打通，不必等训练YOLO才能完善状态机。P2模型数据准备可并行，但模型替换必须保留同感知条件的策略对照。深度健康与陈旧检查进入消费方，不意味着要把所有六类传感器都做融合。

## 5. 新版AirSim必须覆盖的功能用例

- T01：A正常完成，B不接替，任务返回并正确记录。
- T02：目标位置改变，策略未读目标真值仍能获取并执行。
- T03：起始画面无目标，限定区域搜索后发现；无目标场景有界结束。
- T04：短时遮挡后恢复，不把暂失判为完成或立即补位。
- T05：持续丢失/一次未完成，正确进入恢复或接替，原因可回放核查。
- T06：B接替前A让出通道；两机不争用同一任务阶段。
- T07：旧碰撞、错误对象碰撞不能记为目标完成。
- T08：RGB空帧、深度无效、时间戳陈旧，触发明确的等待/退出处理。
- T09：A和B均不能完成，正常记录失败与收尾，不以移除气球冒充成功。
- T10：相似颜色干扰目标，不出现错误目标完成判定。
- T11：两种最终段模式独立记录，坐标兜底不混入无目标真值的视觉成功指标。
- T12：固定版本下多种子重复测试、对照和消融可复算。

每个用例先离线测试关键逻辑，再跑单轮仿真，再重复和扩展条件；新功能未通过时不直接进入批量。已有失败暂停现场需先检查/回收再运行，不能盲目地面重启任务。

## 6. 什么时候迁移实机

AirSim阶段退出条件：P0–P7完成所需范围；T01–T12有明确记录；隐藏目标真值依赖已隔离；重复试验包含失败；核心方法对比强基线有可解释结果；配置/模型/代码与结果对应。验收不要求制造100%成功率，也不等于已经满足某期刊录用条件。
