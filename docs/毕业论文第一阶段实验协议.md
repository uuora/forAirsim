# 毕业论文第一阶段：单机单目标先导实验协议

版本：2026-09-30。本文是先导实验的执行协议，实际结果由每批原始报告确认。现有记录与分母由 `python/build_phase1_evidence.py` 重建，见[第一阶段证据盘点](第一阶段证据盘点.md)；同名 JSON 保存输入报告的 SHA-256，供复核和变更检测。

## 1. 阶段目标与边界

问题 A：在 Blocks 固定红气球与相同起点条件下，视觉闭环策略相对固定航点策略，是否能更稳定地达到预定观察状态？这一步只比较单机 DroneA 的观察阶段；DroneB 必须保持落地。固定场景先导只检验重复性，不给出方法总体优劣结论。

问题 B：在 MaritimeHarborV2 定点观察条件下，颜色/轮廓方法何时把指定红气球误判为相似实例或不产生候选？这一分支只研究实例判别，不包含海面接近航线。云端 VLX 图像＋文字回放可作为探索性参考；仅在确认外部候选框确实被云端接口接收后，才能另立 YOLO→VLX 候选框方法。

两个问题使用不同仿真场景、干预与指标，分别报告，不合并成一个“任务成功率”。

## 2. 固定协议：Blocks 成对控制

| 项目 | 固定做法 |
|---|---|
| 独立性层级 | Unreal 重启后的采集会话为高层单位；同会话内两对试次保留配对关系，并注明相关性 |
| 干预 | `coordinate` 与 `visual`；共享起点、目标、安全边界和终止评价；新批次使用相同 0.15 m/s 三维接近指令速度上限 |
| 主指标 | 每个已开始试次的 `task_success`；`status=PASS` 只说明安全收尾 |
| 辅助指标 | 接近用时（含相机评价，排除起飞/返航）、路径长度、有效检测比例、终点图像误差、最终气球表面距离 |
| 顺序 | 每次会话运行 `--repeats 2`，顺序为坐标→视觉→视觉→坐标；使用 `configs/single_drone_matched_speed.json` |
| 先导规模 | 计划 3 次独立 Unreal 重启，每次 2 对，共最多 6 对/12 次飞行；这是调试与方差估计，不用于显著性主张 |
| 失败处理 | 任一次失败立即停止该批；失败与中断保留在全部已开始试次的分母和原因表中；只有两策略均完成的配对才计算配对用时/路径差 |

已加入自动执行入口：从仓库根目录运行下面命令。脚本指定 Blocks 地图和配置，记录每次进程与场景检查；只有前一会话四个试次安全收尾后才关闭该进程并启动下一会话。

```powershell
& .\scripts\run-phase1-pilot.ps1 -Sessions 3
```

也可双击 `Run-Phase1-Pilot.cmd`。脚本拒绝占用中的 RPC 41451；第二、第三次会话各自重启 Unreal 并重复检查。批次失败后保持仿真暂停，按 `docs/单机单目标实验_第一阶段.md` 的回收流程检查与处理；不直接重跑覆盖失败记录。

2026-09-30 原配置重复性批次 `logs/phase1_pilot_20260930_095742_1368008/manifest.json` 在第二会话第四次试次停止：观察目标已达到，落地验证超时；八次尝试均保留。经暂停现场检查及新遥测确认，DroneA 在返航垫地面，随后有记录地解除武装/控制并确认 Landed。新版本记录逐次落地遥测，以地面 actor、返航垫、相对地面高度和持续两秒低速共同确认物理落地，再解除武装/控制并等待 Landed 标志。

原配置坐标前进参数为 0.7 m/s，视觉前进约 0.15 m/s；旧批次的用时差包含速度设置差异。新统一速度批次使用新源码与配置，分别分析，不与旧数据合并计算方法效果。

实际完成记录：`logs/phase1_pilot_20260930_104530_5529764/manifest.json` 完成三次独立重启、六对配对；两策略各六次任务成功且安全收尾，DroneB 最大记录位移为零。表图见该批次 `analysis/`。此前统一速度批次 `logs/phase1_pilot_20260930_101500_1699329/manifest.json` 中途进程退出，记为 INTERRUPTED；两次完成和一次未形成终态的试次单独保留。后续变化条件须另行预先定义、检查边界并冻结评分，不把本次 12 次固定场景飞行视为正式泛化验证。

横向位置开发先导已执行：`configs/phase1_lateral_pilot/` 预设中心、Y=-0.6 m、Y=+0.6 m；其他控制参数和固定终点一致。`scripts/run-phase1-lateral-pilot.ps1` 每个条件重启一次 Unreal、运行两对试次。`logs/phase1_lateral_sweep_20260930_112257_1344693/analysis/summary.md` 保存实际结果：12 次安全收尾，中心两策略各 2/2 达标；偏移条件固定航点各 0/2、视觉各 2/2。条件与会话混杂，属于开发验证，正式试验应跨会话复现并平衡条件顺序。新增记录保存未标注 RGB 和哈希，后续模型输入使用原图。

## 3. 固定协议：海事定点观察与可见框复核

已有 `logs/maritime_layout_collection_20260926/collection_manifest.json` 记录 3 次 Unreal 进程采集、36 张图像。下一动作是由实际人工复核者打开原图，独立确认指定目标和相似红气球的可见区域，填写 `review_queue.csv`；AirSim 投影框和 AI 建议只能作参考。执行入口：

```powershell
& .\.venv\python.exe .\python\review_maritime_visible_boxes.py `
  .\logs\maritime_layout_collection_20260926\review_queue.csv --reviewer "实际复核人"

& .\.venv\python.exe .\python\validate_maritime_layout_review.py `
  .\logs\maritime_layout_collection_20260926\collection_manifest.json
```

只有校验返回 `READY_FOR_EVALUATION` 后，才把 36 帧用于正式逐帧实例选择评分。汇总按 3 个采集会话列出，避免把连续帧当作 36 个独立场景。若人工复核后发现不可见或身份不确定，逐帧保留该状态，不事后改提示词或移除困难帧。

## 4. VLX 分支的前置门槛

当前 `python/vlx_api_client.py` 的云端请求体发送图像和文本，未发送 `boxes`。因此保存的 `logs/vlx_api_full_test.json` 虽有 30 帧返回与指定目标关联，属于**请求类型未记录的历史云端回放**，不能当作候选框引导方法的比较结果。今后的 `python/vlx_seek_probe.py` 报告会记录 `vlx_backend`、`vlx_request_mode` 和 `vlx_proposals_transmitted`。

在固定图像上进行两组互斥候选框的协议试验，并结合云端接口文档确认外部框字段。如果云端服务支持，就以其文档字段实现并测试；如果不支持，正式比较只设置“图像＋文本 API”条件，候选框引导保留给支持 `bbox_list` 的本地工作流。官方开源 10B 推理接口确实支持原图像素框，但这不能自动证明所用云端 3B HTTP 接口支持同一字段：[官方推理指南](https://github.com/om-ai-lab/VLX-Seek/blob/main/docs/inference.md)。

## 5. 下一阶段进入条件

1. Blocks 至少完成上述 3 次安全独立会话的先导采集，记录全部失败与中断，并检查顺序和会话效应；数量不足时明确继续先导，不提前给出总体结论。
2. 海事 36 张图像具备实际人工 `VERIFIED` 可见框，或明确保留为探索性资料。
3. VLX 的每次记录标明请求类型；没有候选框传输证据时，不使用“YOLO→VLX”命名云端结果。
4. 冻结正式实验的条件、主指标、样本量和分析单位后再扩充数据。正式规模依据先导变异和可用资源确定。
