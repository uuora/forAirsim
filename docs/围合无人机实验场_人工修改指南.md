# 围合无人机实验场：人工修改入口

更新：2026-10-09。本轮交付限于地面场景与几何核查。飞行、识别准确率、绕障控制和双机接替均未在这张新地图上验收。

## 直接打开 Unreal 编辑器

双击根目录的 [工具_编辑实验地图.cmd](../工具_编辑实验地图.cmd)。入口自动准备并打开工作副本，之后再次打开会保留已有编辑结果。

- Unreal 工程：`external/AirSim/Unreal/Environments/Blocks/Blocks.uproject`
- 可编辑地图：`/Game/EnclosedUAVLabManual/Maps/EnclosedUAVLab_Manual`
- 编辑资产目录：`/Game/EnclosedUAVLabManual/Meshes` 与 `/Materials`
- 第一轮验收地图：`/Game/EnclosedUAVLabV1/Maps/EnclosedUAVLab`

工作副本的网格和材质已独立复制并重新绑定。入口不执行 Play。首次启动会先准备副本；已经打开同一个 Blocks 工程时，入口会提示先保存并关闭，防止两个进程同时写资产。无需关闭其他 Unreal 工程。

在 World Outliner 的 `Lab` 文件夹按 `start_platform`、`balloons`、`container` 等分组查找；也可以搜索 `EL1_` 查看场景部件。选中物体后，按 **W 移动、E 旋转、R 缩放、F 聚焦**；在 Details → Transform 精确输入 Location、Rotation、Scale。Unreal Location 使用厘米：例如 X=1700 表示 17 米。这里的盒子和球基础直径/边长为 1 米，因此 Scale `[3,3,5.5]` 对应盒子尺寸 `3×3×5.5 m`。

常用标签：`EL1_StartPlatform`（起点）、`EL1_TargetPlatform`（目标平台）、`EL1_TallBlock`（高障碍）、`EL1_Balloon_Target`（带白条红球）、`EL1_Balloon_RedDistractor`、`EL1_Balloon_YellowDistractor`。

平台、集装箱、长椅、门架等由多个部件组成。整体移动时在 Outliner 选择同组部件一起移动，避免只移动实体而留下标线、支架或饰面。Ctrl+W 可复制障碍；即使显示标签相同，导出器也以独立的 Unreal Actor 名称区分它们。

建议从已有盒状障碍复制新障碍。球体保持 XYZ 一致缩放。颜色通过本工作副本 `/Materials` 中的材质调整。直接添加其它模型允许编辑，但只会在明确核对其碰撞与规划几何后成为通过验收的对象；当前导出器会报告未知碰撞网格，不能直接给它通过结论。

无人机由 AirSim 运行时按 settings 生成，普通编辑器地面地图里显示 H 起降位。第一轮实际画面中已有两架无人机。编辑入口使用独立的 `configs/enclosed_uav_lab_manual_settings.json`（Multirotor、DroneA/DroneB、API 端口 41454），避免读取以前的车辆配置。修改起点平台后需另行对齐该文件中的无人机生成位置；本次入口不自动 Play、开始飞行或修改控制配置。

## 保存后导出几何并检查

1. 在 Unreal 执行 **File → Save All**，保存地图与材质，然后关闭该工程编辑器。
2. 双击 [工具_检查已保存地图.cmd](../工具_检查已保存地图.cmd)。
3. 查看自动打开的 `reports/enclosed_lab_manual_时间戳` 目录。

输出包括 `scene_geometry.json`、`planning_geometry.json`、`geometry_correspondence.csv`、`geometry_check.json` 和 `provenance.json`，还保存工作地图及其网格/材质的 `unreal_asset_snapshot` 与导出器源码。每次生成新目录，保留历史记录，供后续实验和论文核对。

`PASS_SAVED_EDITOR_GEOMETRY` 表示：已保存的地图通过本轮有限几何检查。可见盒网格对应 BOX 碰撞和规划 OBB（包含旋转）；球对应 SPHERE 碰撞和规划球；无碰撞的饰面不加入规划障碍。门架按柱和梁分别记录，保留中间空隙。

检查读取真实 Actor 位置、尺度、方向、材质、碰撞设置，核对每个原语的六条轴向表面线段及三条外侧线段。容差：盒状可见边界 5 mm，碰撞表面采样 15 mm。球的物理/规划表面是解析球，渲染网格是多边形近似。检查还拒绝非等比球、未知碰撞网格、不可见碰撞体和不支持的碰撞设置。失败时查看 `problems`；输出数据仍可审阅，但不能当作已通过的规划输入。

OBB 字段 `orientation_axes` 分别为局部 X/Y/Z 在世界坐标中的单位方向。几何使用米、Z 向上；AirSim NED 的 Z 向下。规划控制程序尚未接入这些人工修改结果，不能把 Z 向上的数据直接交给 NED 控制器。

## 精确参数修改入口

双击 [工具_编辑地图参数.cmd](../工具_编辑地图参数.cmd)，用记事本打开 `configs/enclosed_uav_lab_manual.json`。位置 `center_xyz_m`、尺寸 `size_xyz_m` 均使用米；`material` 使用既有颜色键。碰撞/规划边界由生成器从位置和尺寸重新计算，旧的缓存边界不作为依据。

保存 JSON 后，双击 [工具_按参数重建地图.cmd](../工具_按参数重建地图.cmd) 重建并检查工作地图。这个操作会用 JSON **替换工作地图中 `EL1_` 的部件**，因此编辑器内的人工调整应先导出，不能期待两种修改方式自动合并。编辑器导出的 `scene_geometry.json` 是实测几何记录，不会自动回写参数 JSON。

参数构建目前生成轴对齐原语；需要旋转布局时在 Unreal 中操作并导出 OBB。修改围墙、起点或目标平台时，文字标签、拍摄相机、settings 与派生平台间距需同步审阅；本入口不把未经同步的参数声明为完整实验配置。
