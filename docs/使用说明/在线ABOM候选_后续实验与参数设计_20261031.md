# 在线ABOM候选：后续实验、参数与展示

本文件是可执行研究任务书，不是导师汇报稿。已实现与拟实现分开标注。当前为AirSim纯控制仿真，无障碍物、无相机/感知输入；固定底层反馈控制器。Bézier/Hermite共用物理曲线域，本阶段先固定Hermite研究搜索机制，不能把换基当创新。

## 1. 先修正研究问题

目标是：**满足跟踪与实时约束时，以较少的昂贵代理评价完成更多/更快的目标通过任务。**

三个需要分别回答的问题：

1. 候选优化是否减少实际到达第k目标的时间，或者提高固定任务时长内的过点数？
2. 在相同单次规划墙钟预算下，能否减少完整代理调用与无效重规划，同时保持任务成功和跟踪精度？
3. 哪部分收益来自配对扰动，哪部分来自通用的到达时间约束、搜索域缩小和计算资源分配？

旧种子1201的三条真实记录显示：原配对候选8次执行切换中7次推迟当前目标的计划到达时刻；正推迟账目合计7.171秒、净变化+6.612秒。这不是实际飞行延误的因果估计。基础ABOM在25秒内同样通过4点，但第4点比普通曲线早1.794秒，同时误差更大；只看整数过点数或RMSE会漏掉速度—精度取舍。

旧记录代理评价＋验证约占搜索工作进程墙钟90%，网络生成＋更新约占3%。据此，本轮优先研究评价调用分配和任务进度一致性；不能未经测量就把网络规模当主要瓶颈。

来源：`logs/dual_target_airsim_20261031_132139_757279`（普通）、`132033_119671`（基础）、`132257_178654`（原候选）的状态、事件、参考窗口与逐调用日志。诊断只用原始记录，未改写结果。

## 2. 本轮已实现的候选机制

每次请求优化未来两段曲线：

\[
\theta=(d_{x1},d_{y1},d_{z1},T_1,d_{x2},d_{y2},d_{z2},T_2).
\]

五次端状态基线上叠加六次C2位移扰动，两端位置、速度、加速度保持。原形状域为每段±(0.8,1.4,0.8)米，时长3–7秒。

**G：不推迟已承诺的当前目标到达时刻。** 已承诺时刻为a，候选开始执行时刻为h：

\[
3\le T_1\le\min(7,a-h).
\]

若a−h≤3秒（含数值保护），该参数域内没有可优化的非退化可行时间区间，跳过本次搜索。这个规则证明的是当前参数域内的不可行，不能声称无人机物理上无法更快到达。若缩短后的解析anchor不通过运动学检查，同样继续现有参考，不启动昂贵搜索。接收端再检查h+T1≤a。

**L：局部形状域。** 在G基础上，把6个形状变量的物理范围缩小为原范围的0.25，即每段±(0.20,0.35,0.20)米；时间域不乘0.25。该限制同时作用于网络与配对提案，不应误称仅调整高斯噪声。

基础ABOM、原配对候选的默认行为保留。新机制仅在显式研究脚本的处理组启用。网络仍在每个滚动搜索窗口重新初始化；跨窗口热启动尚未实现。搜索评价仍为简化模型，AirSim搜索调用数仍为0。

## 3. 本轮冻结的六臂试验

这六臂是**机制消融**，不是原来Bézier/Hermite×三搜索方法的六组。

| 臂 | 方法 | 用于回答 |
|---|---|---|
| O | 普通Hermite | 无搜索任务/误差/开销基线 |
| A | 基础ABOM | 搜索相对普通参考有何取舍 |
| P | 原配对扰动候选 | P−A：配对机制是否有效 |
| AG | 基础ABOM＋G | AG−A：通用时间约束是否有效 |
| PG | 配对候选＋G | PG−P：时间约束；PG−AG：同约束下配对是否有效 |
| PGL | 配对候选＋G＋L | PGL−PG：局部形状域是否有效 |

共同条件：新目标种子1301，每臂25秒；起点(0,0,5)；固定目标序列/哈希；规划只见当前与下一点；共同控制器、物理模型、6m/s速度指令上限、6m/s²指令变化率、偏航提前量0.18秒、20度过点朝向门槛、0.5米位置峰值门槛、0.1秒状态间隔保护。

每个优化任务墙钟上限0.8秒，预留0.10秒给最终验证；种群8、网络容量相同、dropout0.95、学习率0.001；配对比例0.5、初始归一化尺度0.15。候选数上限100000仅防失控，实际由墙钟截止；区别于旧32候选开发试验，不能直接合并排名。普通曲线只做代理验证。

执行顺序由种子461预先打乱。先写`design_frozen.json`及哈希，再开始飞行；每臂独立目录。飞行失败保留，降落/关闭无法确认时中止后续。看到1301结果后不调参重跑替换。本轮每臂1次、仅1场景，不做显著性判断；1301在本轮后成为已观察验证场景，不再作为未来新留出数据。

完整配置条件指纹仍保留；额外研究控制指纹只排除事先声明的算法处理字段`online.research`和方法名。报告再次比较实际配置，确认地图、控制器、目标、预算和源码一致；普通数据对比器仍保持严格完整指纹规则。

## 4. 参数应该从哪里改

先分清物理轨迹变量、搜索器参数和共同控制器参数。下面候选取值是**后续开发网格**，不代表已全部测试或最优。

| 层次/参数 | 当前/本轮 | 下一轮开发取值 | 预期作用与风险 | 状态 |
|---|---|---|---|---|
| 当前目标到达时间上界 | 无约束 vs G | 固定不推迟；未来允许明确惩罚的松弛量0/0.1/0.2s | 防局部重规划不断延后任务；可能拒绝必要修复 | 本轮实现G，松弛未实现 |
| 形状域倍率 | 1 vs 0.25 | 0.25/0.5/1 | 小域可能降低跟踪难度但损失捷径 | 已可配置 |
| 配对初始尺度σ | 0.15 | 0.05/0.10/0.15/0.25 | 过大跨入不可行区，过小搜索无效 | 已可配置；群体宽度还会缩放各维噪声 |
| 配对比例ρ | 0.5 | 0/0.25/0.5/0.75 | 网络提案与局部提案的资源分配 | 已可配置；数量取偶数，记录实际比例 |
| 种群N | 8 | 4/8/16 | 大种群增加初始评价成本，短预算可能来不及更新 | 已可配置；须偶数 |
| 规划墙钟B | 0.8s | 0.2/0.4/0.8s | 观察有效质量与实时性如何变化 | 已可配置，验证计入 |
| 每次提案数 | 旧32，本轮仅防失控上限 | 固定墙钟主试验；离线等候选数32/64补充 | 避免把候选更少误写成同预算搜索更好 | 主试验已接入 |
| 触发间隔 | 结果返回后2s | 1/2/4s或收益/状态触发 | 少搜索省调用，过少可能错过有价值修正 | 事件触发未实现 |
| dropout/学习率 | .95/.001 | .5/.8/.95；.0003/.001/.003 | 影响网络探索/适应；需同容量比较 | 已可配置，但先不优先调 |
| 过点参考速度 | 1.2m/s | 共同开发档1.2/2/3m/s | 当前指令上限6不等于实际高速；须统一冻结 | 未作为优化变量接入 |
| 起始/终止段T下限 | 3s | 从状态及动态约束推导下界 | 固定3秒限制敏捷性；不能直接绕过解码器约束 | 未实现 |
| 跨窗口精英/网络复用 | 无 | 冷启动/仅精英/仅网络/两者 | 可能省初始化和评价，也可能负迁移 | 未实现，需状态/目标相似性门控 |
| 代理滞后与偏航 | τ=.9s，无完整偏航模型 | 用独立开发飞行识别τ/偏航响应 | 代理排名迁移不可靠，不能按测试胜负反调 | 待模型校准 |

底层位置/速度增益、偏航增益、指令限幅不是给每个算法单独调的参数。若为高速档重新标定，先在独立开发任务统一标定，再冻结；新协议整组重跑。禁止放宽门槛把旧失败变成成功。

## 5. 后续实施顺序与实验量

### 阶段A：同一冻结状态上的黑箱评价诊断（开发集）

从旧1201任务提取9个不同阶段的两点规划请求，固定完整边界、目标和预算。各搜索器重放同一个请求，避免把不同在线状态的代理分数平均在一起。用12个搜索种子、0.2/0.4/0.8秒预算；先比较A/P/PG/PGL，再逐项做σ、ρ、N的小网格，不做全笛卡尔积。

保存每候选的参数、便宜检查、完整评价起止、当前最好可行值与截止期。展示预算—最好可行质量曲线；预热和每次网络初始化分别报。补32/64等候选数（包含初始种群）的离线试验。初始参考已可行，首次可行时间不能用于证明提效。

候选参数选择规则事先约定：先满足可行性/截止期要求，再看跨开发请求中位改善及最差退化；若没有一致收益，保留默认或缩减研究主张。不能用新的AirSim验证种子选参数。

### 阶段B：冻结后AirSim主比较

建议O/A/PG/PGL四组，12个从未观察的路线种子1401–1412 × 3个独立优化随机种子21/22/23，共144次、每次40秒。**当前代码搜索种子与场景种子绑定，需先补独立optimizer_seed接口，才能执行这个设计；同种子重复不能伪称独立搜索种子。**

六臂机理消融可在其中预先选定的4个场景追加P/AG，共24次，完整揭示G是否对基础ABOM同样有效。每个场景/优化种子块内轮换方法顺序；失败/超时均保存。同一硬件上串行飞行，避免并行测试制造控制时序负载。

主要报告固定任务时间内目标数、到第k点时间、任务完成/跟踪通过；以误差、调用次数、延迟形成Pareto比较。以整条飞行为观测单位，按场景做配对分析；场景为簇进行bootstrap区间，不能把50Hz状态或每个搜索窗口当独立样本。12场景是可执行的起点，不是自动保证统计功效；用开发方差检查后再冻结样本量。

### 阶段C：预算与资源曲线

在预先选择的4个新场景、3个优化种子、3个预算上比较A与选定候选，共72次。报告端到端任务效果、每个通过目标的完整评价、每秒飞行的评价数、截止期失效率、P50/P95/max延迟。另加独立进程CPU时间、峰值RSS、控制线程P95/P99周期监测；**本轮只有墙钟及调用账，不把它们称为CPU占用或内存节省。**

### 阶段D：鲁棒性与敏捷性（独立协议）

优先选可解释场景：长直段、60度转向、接近100度转向、爬升后转向。当前随机流方向余弦≥−0.4，不覆盖原地掉头。初态偏差、真实模型失配、外扰、下一目标更新分别单因素测试，再少量组合；更改物理或初始化则形成新条件组，各算法共同重跑。

初态误差须通过真实移动/启动状态实现，不能瞬移；记录实际偏差。动力学失配须改变实际被控对象条件，仅改离线τ不算AirSim失配验证。外扰接口需验证支持并记录施加/撤销时刻。当前尚未实现这些鲁棒性接口。

高速阶段先把共同参考速度和可行T域升级到统一档位，实测速度、加速度、偏航跟踪及峰值误差；不能用6m/s的指令上限证明“高敏捷”。无电机数据时不声称电机饱和或执行器动力学验证。

## 6. 性能展示应有六个维度

| 图/表 | 主要回答 | 应避免的误解 |
|---|---|---|
| 累计过点阶梯＋time-to-k | 真正更早到目标吗 | 未达到不能填25秒当完成；须标未达/删失 |
| 任务速度—RMSE/峰值Pareto图 | 更快是否以误差换取 | 不能仅以综合分宣布胜出 |
| 每次参考绝对到达时刻变化 | G确实抑制计划拖延吗 | 变化账目之和不是实际耗时的因果估计 |
| 评价/验证/训练/初始化堆叠＋每目标调用 | 计算省在哪里、是否做了有效工作 | 工作墙钟与飞行重叠，不能直接相加；CPU另测 |
| 同状态预算—最好可行质量曲线 | 相同黑箱问题上搜索是否更高效 | 不把不同在线状态的局部分数混比 |
| 延迟ECDF、候选流转、失败清单 | 能否及时采用、有多少无效搜索 | 提交、选中、安排切换、实际执行是不同计数 |

另外保留真实轨迹叠加、同步误差、速度/指令和源数据链接。参考/实际折线只是位置证据，不冒充完整姿态验证。学习收敛图可加，但不得代替任务效果。

## 7. 创新性与证据边界

可继续研究的机制表述是“任务进度约束下的ABOM候选生成与评价资源分配”。本轮的G是通用时间可行性机制，AG是必要对照；如果AG已获得全部收益，就不能把它全归功于配对扰动。L是搜索域限制，必须与同容量、同预算、同控制器比较；若只是缩小范围的收益，需要如实说明。

跨窗口热启动、状态驱动σ/ρ、自适应评价筛选可能形成进一步方法，但当前尚未实现或证明创新性。便宜下界筛选应以最差保留父代为比较阈值才能保留原精英选择语义；只按最优解阈值删除子代可能改变种群更新。需先证明界，再做关闭筛选/启用筛选的同候选流消融。

文献只支持方法背景：COCO把目标函数调用次数作为黑箱优化的重要运行成本，并区分目标质量与预算条件（[原始论文](https://arxiv.org/abs/1603.08785)、[官方实验流程](https://numbbo.github.io/coco-doc/experimental-setup/)）；本项目另外统计墙钟，因为网络/通信也有成本。实时迭代已有长期研究（[Diehl等，CDC-ECC 2005](https://skoge.folk.ntnu.no/prost/proceedings/cdc-ecc05/pdffiles/papers/1186.pdf)）；异步/热启动本身不应宣称首创，也不能把MPC稳定性结论套用到这里的黑箱候选搜索。

本设计与代码由AI研究开发助手协助构建；最终科学结论需由原始数据、独立复核和后续重复验证支持。
