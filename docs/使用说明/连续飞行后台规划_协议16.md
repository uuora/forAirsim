# 连续飞行与后台规划（协议16，开发验证）

## 运行

关闭旧版工作台，重新打开根目录“打开轨迹实验面板.cmd”。在准备点设置区点击“连续飞行 · 后台规划（协议16开发版）”。这只切换空闲工作台，不起飞。选择六种方法之一，设置起点、目标种子、飞行时长，再启动仿真并点击“开始连续飞行”。默认25秒、种子1201；不默认依次运行六种方法。

原03入口、地图、物理配置、实际起降及原生鼠标观察方式保留。在线模式采用统一的时序参考跟踪器，并非直接把原03的 RollingController 换一个优化参数。无障碍物、无感知输入、不生成相机截图。

## 飞行时发生什么

1. 真实起飞，到可修改起点收敛，位置≤0.02米、速度≤0.03米/秒、朝向≤0.03弧度，连续5次；不瞬移。
2. 立即执行通过运动学检查的解析后备参考。规划进程的导入/预热不要求飞行线程等待。
3. 当前与下一目标已知时，独立进程规划未来两段参考。默认每次最多32个搜索候选（种群8）且墙钟上限0.8秒，最终代理验证也计时。常规搜索完成后约2秒再尝试；临近过点或任务结束时不发起来不及切换的工作。
4. 为参考时钟未来1.3秒的状态冻结位置、速度、加速度边界。候选及时返回、目标及参考版本未变、简化模型及父进程运动学检查通过、当前跟踪误差≤0.5米，才安排切换。位置/速度/加速度（C2）均须连续，控制指令还受6米/秒、6米/秒²及偏航120度/秒约束。
5. 迟到、过期、验证失败或仍为原始锚点，继续已有参考。**后备轨迹通过运动学检查不等于对实际飞行作安全保证。**超过2米偏差紧急终止，超过0.5米仍判跟踪门槛失败；没有放宽旧门槛。
6. 通过目标后释放下一目标，衔接新后备参考并继续后台计算。漏点不计成功、不跳过；失败与用户停止均降落并保存。

目标流事先按种子固定并保存哈希，不依赖无人机实际位置。规划进程每次只得到两个目标；完整序列仅供复现和固定视图取景。当前开发目标间距6–9米，相邻方向余弦≥−0.4，x/y在±24米，高度4–10米；不能外推到任意随机掉头场景。标记球只是坐标标记，不是障碍物，也不是撞击任务。

## 六种方法具体改什么

普通曲线使用五次端状态插值基线。优化方法在每段加入保持端状态的六次C2位移扰动，并搜索时长；两段联合8维：`[dx,dy,dz,T]×2`，位移范围±(0.8,1.4,0.8)米，时长3–7秒。

Bézier/Hermite共用端状态和同一物理参数域，属于同一曲线族的表示，换基不是性能创新。基础ABOM是固定上游网络的本地适配；候选版将一半子代改为自适应成对扰动，不是已证实的新算法或完整原文复现。网络/精英在单次后台搜索内继承；不同滚动窗口的网络仍重新初始化，**尚未实现跨窗口网络热启动**。

代理使用0.9秒一阶速度滞后质点、0.04秒积分与固定位置/速度反馈，AirSim只执行被承诺的参考，**AirSim搜索调用数为0**。代理尚未完整表达偏航响应与真实飞行动力学，代理最优不能当作AirSim最优。本模式没有调用已发现掉头死区、排序不可靠的旧 `trajectory_objective.evaluate_parameters`。

偏航统一朝当前目标，并使用固定0.18秒视线角速率提前量补偿开发试飞中观察到的滞后；六方法相同。前两次未补偿/未充分补偿的失败记录保留；不同控制版本按指纹分开，不混排。

## 数据在哪里、怎样评判

本次界面“运行记录”打开 `logs/dual_target_airsim_时间戳`；“本次轨迹与数据图”打开 `online_result.html`。返回记录库后可按协议16筛选、查看、勾选对比；新方法对比需相同种子、时长、控制器、物理条件和源码指纹。协议13/14/15不与16混排。

| 文件 | 含义 |
|---|---|
| online_states.jsonl / online_states.csv | 仿真时间戳、实际位置/速度、同一时刻参考及指令、执行窗口编号 |
| online_reference_windows.json | 每次参考及未来切换时间、完整参数、C2边界 |
| online_events.jsonl | 搜索提交/返回、采用或拒绝原因、过点、中止 |
| online_worker_evaluations.jsonl | 每次代理评价/验证开始与完成；中止时保留已完成及未完成调用 |
| online_manifest.json / source_snapshot | 场景、协议、条件指纹、目标流哈希、控制/网络源码快照 |
| online_preparation.json / takeoff.json | 实际准备与起飞过程，不混入参考跟踪RMSE |
| online_metrics.json / online_metrics.csv | 指标和中文解释 |
| online_trajectory.png / online_tracking.png | 已执行参考/实际轨迹、原始误差、速度和切换图 |
| summary.json | 完成/中止/失败及跟踪门槛；定时完成不等于控制通过 |

主要看相同执行时间内通过多少目标，以及同步位置RMSE、峰值误差≤0.5米、状态最大间隔≤0.1秒、碰撞/失败。RMSE是同一仿真时刻位置差的时间加权均方根，越小表示跟踪越准。在线无限目标流没有统一静止终点，不套用固定路线终点综合分。

资源看提交至完整结果收件的墙钟延迟、超时/过期数、代理完整调用数、网络初始化/生成/更新及验证时间、启动预热开销。规划与飞行重叠，不能把所有规划时间简单加到飞行时长。速度指令限幅比例是采样比例，不是电机饱和。已安排切换不等于已执行，结果单独统计两者。

三种Hermite方法的单次开发覆盖只验证接口与数据链路，不做显著性判断。暂不声称改进候选提高成功率、降低误差或整体优于基础ABOM。下一步应冻结控制器后增加新种子、重复次数，比较等墙钟下质量，并验证跨窗口精英/网络复用能否减少计算；需要同容量消融。

## 可复现开发入口

```powershell
cd D:\forAirsim
$env:PYTHONPATH='D:\forAirsim\python'
.\.venv\python.exe -m unittest dual_target_control.test_online_control -v
# 已有数据独立重算（不调用AirSim），输出在原始日志之外：
.\.venv\python.exe python\audit_online_control.py logs\自己的运行目录 --output reports\自己的审计目录\audit.json
# 下句会实际起飞，独立保存，非默认批量入口：
.\.venv\python.exe python\verify_online_control.py --airsim --method hermite_abom --duration 25 --output reports\自己命名的全新目录
```

需要继续改善的是代理偏航/姿态表达、极端转向、新目标突然变化及跨窗口热启动。还应检查重规划是否推迟既定过点时刻：局部两段综合分改善不保证整段任务过点更多。异步计算、截止期、连续衔接与后备机制属于本次系统实现，不凭这一次实现主张研究首创。
