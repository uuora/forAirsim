# 完整控制实验：复现步骤与评判标准

本轮执行目录：`reports/control_full_flow_20261101_v1/`。最终结果入口是其 `analysis/index.html`，原始目录逐条列在 `campaign.json`。这是一轮当前实现的完整开发验证，覆盖固定路线、在线机制与相同请求搜索诊断；高速、真实外扰和大样本统计仍需后续独立实验。

## 1. 我们检验什么

1. **流程与控制接口**：先实际飞到准备点，再规划和跟踪；状态与同一时刻参考对齐，满足共同误差和航点门槛。
2. **固定路线的搜索效果**：普通曲线、基础ABOM、配对扰动候选分别在Bézier/Hermite表示下执行；逐点停稳和连续过点各比较六方法。
3. **连续飞行中的计算是否有效**：飞向当前点时，后台只利用当前／下一点计算；新参考在未来时刻连续接入。既比较过点进度，也比较计算成本。
4. **候选改动来自哪里**：时间约束、缩小形状域和配对扰动分别设对照；加入同域高斯搜索，检验网络是否有额外贡献。

ABOM修改的是参考轨迹参数的搜索过程。执行时，各方法使用相同的状态反馈控制器。当前黑箱评价为简化动力学模型，AirSim用于真实闭环执行；**AirSim搜索调用为0**。网络每个在线窗口重新初始化，窗口内继承精英与网络参数，尚无跨窗口网络热启动。[实现](../../python/online_curve_worker.py)

## 2. 本轮冻结矩阵

### 固定路线：12次

准备点 `(-3,1,5)`；航点 `(8,0,5)→(12,6,7)→(6,10,6)`，高度向上，单位米。任务种子1201。六方法各运行 `stop` 和 `pass` 一次，运行顺序事先打乱。

| 任务组 | 中点要求 | 末点要求 | 方法数 |
|---|---|---|---:|
| stop逐点停稳 | 停留1秒，停留结束检查速度 | 停稳 | 6 |
| pass连续过点 | 参考过点速度1.2m/s，按计划时刻检查实际速度 | 停稳 | 6 |

普通方法1次模型验证；基础和配对候选各80次整路线模型搜索＋1次选中验证，种群20。这是等候选开发设置，不能据此宣称固定墙钟预算优势。两种曲线使用等价物理曲线族，换基差异不作为创新点。[协议15实现](../../python/dual_target_control/prepared_route_live.py)、[搜索入口](../../python/prepared_route_planner.py)

### 在线机制：24次

三组配对块：场景种子1401／优化种子21、1402／22、1403／23。每块八方法，每次40秒；同一块共享目标流、控制器、物理、约束和预算。优化种子已经与场景种子拆开；本轮每场景仅一个优化种子，尚不能单独估计两类随机性。

| 代号 | 方法 | 时间约束G | 局部形状L |
|---|---|---|---|
| O | 普通Hermite参考 | 无搜索 | — |
| A | 基础ABOM | 关 | 原域 |
| P | 原配对扰动候选 | 关 | 原域 |
| AG | 基础ABOM | 开 | 原域 |
| PG | 配对候选 | 开 | 原域 |
| AGL | 基础ABOM | 开 | 原域的0.25 |
| PGL | 配对候选 | 开 | 原域的0.25 |
| RGL | 高斯局部精英搜索 | 开 | 原域的0.25 |

在线每个搜索任务0.8秒，含初始化、生成、评价、训练和选中验证；验证预留0.1秒，种群8。100000候选只是防失控上限，实际由墙钟终止。若超时、过期、运动学／模型检查失败或跟踪偏离，继续已有参考。普通组也有公共进程启动和验证成本，完整保存。

**计时边界缺口：**0.8秒从父进程准备好请求、设置截止时刻后开始，覆盖提交／工作进程／收件检查；父进程之前的`fallback/reference_checks`，以及收件后的解码／可行性复查尚未分段计时。因此本轮在线的累计工作墙钟不能称为完整规划总开销，也不能单靠这些数据宣称端到端规划计算提速。固定路线的完整规划墙钟则从子进程启动计到完成。后续需把请求准备与复查纳入统一计时，并减少控制线程同步计算。[在线调度](../../python/dual_target_control/online_live.py)、[研究请求准备](../../python/dual_target_control/online_study.py)

G将新方案的当前目标绝对参考到达时刻限制为不晚于已有承诺。当现有参数域的最短段时长3秒已无法满足该限制时，跳过此次搜索。G限制的是计划时刻，实际飞行能否更早仍由状态日志检验。

L仅缩小两个段的六个形状扰动量：每段原域 `±(0.8,1.4,0.8)m` 改为 `±(0.2,0.35,0.2)m`，不缩小时间域。两段共8维：每段三维形状位移＋一维时长。配对比例0.5、归一化初始扰动尺度0.15、dropout0.95、学习率0.001，网络容量固定。RGL使用同样种群、精英保留、边界和预算，生成高斯扰动，不训练网络。[研究配置](../../python/dual_target_control/online_study.py)

## 3. 真实执行顺序

1. 检查工作区、依赖、旧记录、地图和当前仿真占用，保存本轮冻结配置与哈希。
2. 启动原03地图，连接状态接口，确认空闲时不起飞且不产生已规划曲线。
3. 实际起飞并移动到准备点；收敛位置、速度、偏航后，固定路线才开始所选方法搜索。在线任务先执行后备参考，后台异步计算。
4. 以仿真时间戳采集实际位置、速度、参考位置／速度／加速度、指令、偏航和事件。实时物理不中断，不瞬移、不生成障碍物。
5. 每项结束降落，确认关闭后进入下一项。控制失败／超时保留；落地无法确认则停止后续调度。
6. 所有飞行完成后再运行审计和绘图，避免与50Hz控制竞争。分别检查记录一致性、任务完成和控制通过。
7. 在同一个冻结请求上运行离线预算诊断，比较相同黑箱问题的质量与耗时。该结果单独标记，不充当AirSim飞行证据。
8. 对比原始点、配对差、任务进度和开销拆分；失败进入分母，未达第k点留空，不填最大任务时长冒充完成。

## 4. 什么才叫通过

### 固定路线

| 项目 | 判据 |
|---|---|
| 到准备点才规划 | 位置≤0.02m、速度≤0.03m/s、偏航≤0.03rad，连续5次满足 |
| 悬停规划保护 | 偏离准备点>0.5m或规划>180秒失败 |
| 同步采样位置峰值 | ≤0.50m |
| 末点位置误差 | ≤0.25m |
| 末点速度 | ≤0.50m/s |
| 各航点位置误差 | ≤0.50m |
| stop中点速度 | 停留结束时≤0.30m/s |
| pass中点速度 | 计划过点时≥0.50m/s |
| 最大状态采样间隔 | ≤0.10s |
| 完整通过 | 正常COMPLETED、控制门槛全通过、独立审计通过 |

RMSE没有另设通过阈值。它是同步位置误差平方的时间平均再开方，单位米；0.08m表示均方根误差8厘米，不能直接称平均误差8厘米。

综合Q只辅助比较相同规则下的可行解：

`Q = 0.7 T/(T+5n) + 0.1 J/(J+30n) + 0.2 RMSE/(RMSE+0.25)`。

T为参考总时长，n为航点数，J为参考jerk能量。越小越好；Q并不消除速度／精度取舍，也不适用于在线目标流。[独立重算](../../python/dual_target_control/curve_audit.py)

### 在线连续飞行

- 目标命中：实际位置运动线段进入目标0.5m范围，入口机头误差≤20°；这是坐标判据，不是物理撞球。
- 同步采样峰值误差≤0.5m、状态间隔≤0.1秒；时间严格递增，参考位置／速度／加速度能重建，C2衔接、参考窗口ID和源码快照一致。
- 完整通过：正常完成40秒＋跟踪检查通过＋独立审计通过。在线没有静止终点，也不套用固定路线终端门槛／Q。
- 搜索结果能否采用另行统计：按期收件、安排切换和实际执行是不同计数。

在线审计的`audit_passed`代表记录自洽，单独看它不足以判控制成功，必须同时看`tracking_checks_passed`和`outcome`。[在线报告](../../python/dual_target_control/online_results.py)、[独立审计](../../python/audit_online_control.py)

运行保护可能在异常状态写入完整采样表之前触发。例如检测到0.102秒间隔后立即降落，之前已保存的样本仍可能通过跟踪重算，但`outcome=FAILED`仍必须判为失败；不能只看RMSE或`tracking_checks_passed`。

## 5. 怎样判断算法表现

| 角度 | 主要指标／图 | 能回答的问题 |
|---|---|---|
| 任务进度 | 固定40秒过点数、到第k点时间、累计过点阶梯 | 是否真正推进任务 |
| 跟踪精度 | 同步RMSE、峰值、末点／航点误差 | 更快是否牺牲误差 |
| 计算资源 | 完整代理调用、每通过目标调用数、累计搜索墙钟 | 计算是否做了有效工作 |
| 开销组成 | 启动／初始化／评价／训练／验证 | 时间花在哪里 |
| 实时性 | 收件P50／P95／最大延迟、超时／过期数、控制采样间隔 | 是否及时产生可执行方案 |
| 机制 | 原定过点时刻被推迟次数、跳过搜索数、采用来源 | G、L与配对各起什么作用 |
| 同问题搜索 | 相同请求的固定预算最好可行质量、等32候选补充 | 搜索器本身是否有效 |

累计工作墙钟与飞行重叠，不能直接相加当任务用时。本轮没有CPU时间、峰值内存或电机数据，不能把调用减少写成CPU／内存／电机负担下降。

特别关注 `PGL—AGL`（配对是否额外有用）、`PGL—RGL`（网络是否必要）、`PG—P`（G是否有用）、`PGL—PG`（L是否有用）。这些是机制比较，不要求某方法每个指标都第一。

每个整次飞行才是一个观测，不能把50Hz样本或搜索窗口当独立重复。三场景开发覆盖只展示原始值、范围和配对差，不作显著性结论；后续再冻结多场景×多个独立优化种子的样本量。

## 6. 如何运行／看数据

日常选择运行仍打开根目录`打开轨迹实验面板.cmd`；固定路线选择任务组与方法，在线模式点“连续飞行·后台规划”。打开窗口和切方法不会起飞。

显式复现本轮完整批量时，使用新的唯一输出目录（不会覆盖已有结果）：

```powershell
Set-Location D:\forAirsim
$env:PYTHONPATH='D:\forAirsim\python'
$env:PYTHONUTF8='1'
$env:QT_QPA_PLATFORM='offscreen'
& .venv/python.exe -u python/run_control_full_flow.py --airsim --output reports/新的完整批次
# 飞行全部结束后：
& .venv/python.exe python/analyze_control_full_flow.py reports/新的完整批次
```

只跑一部分加`--sections fixed`或`--sections online`。研究八臂由专用批量脚本显式启动，不混入日常六方法菜单。批量期间不另外启动飞行、测试或绘图任务。

只复现一个研究机制，例如1401场景的PGL，使用：

```powershell
& .venv/python.exe -u python/run_online_mechanism.py --airsim --arm PGL --scene-seed 1401 --optimizer-seed 21 --duration 40 --budget 0.8 --output reports/新的单次PGL目录
```

`--arm`可选O/A/P/AG/PG/AGL/PGL/RGL。日常GUI的“改进候选”仍是原配对候选P，不能把它当作本轮PGL。新机制用上面的明确入口复现；单次目录含冻结请求、运行回执和独立审计，轨迹图仍在对应原始运行目录。

最终先打开本轮`analysis/index.html`。表格给出每条记录，图展示取舍；CSV为机器与表格工具读取，`results.json`含审计、失败及未运行清单。原始`logs/dual_target_airsim_时间戳/`中的状态、指令、参考和事件仍保留，不靠图像截图证明控制效果。

## 7. 之后优先做什么

1. 先看这轮完整数据：若AGL或RGL与PGL相当，就缩减对配对／网络的贡献主张，优先解释G和局部域的收益。
2. 在旧开发请求上调扰动尺度σ、配对比例ρ、局部域倍率；固定预算0.2/0.4/0.8秒检验；验证场景只评估，不反向调参。
3. 完善代理偏航与滞后识别，做代理预测与AirSim执行的配对迁移检查；当前窗口代理分数不能代替全任务效果。
4. 冻结后增加独立路线×独立优化种子；再做预算曲线、统一高速档、真实初态偏差／外扰接口。尚未实施的鲁棒性不得写成已验证。
5. 在线优先补齐父进程请求准备、筛选、收件复查、RPC与控制周期的分段计时。现有两次采样保护失败尚无充分原因证据，需先定位，再把计算迁出控制线程；新协议下重跑，保留本轮失败。

本说明与分析程序由AI研究开发助手协助完成。科学结论以链接的原始日志、完整失败记录和独立重算为依据；本轮不作首创或普遍性能提升声明。
