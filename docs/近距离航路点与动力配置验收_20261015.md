# 近距离航路点与动力配置验收（2026-10-15）

当前默认配置已调整为相邻随机航路点三维距离 **6～12 米**、整机模型质量 **1 kg**、标称推重比 **2.5**。AirSim 插件已重新编译，实际启动回执核验总最大推力约 **24.516626 N**。90 秒控制记录中，19 个目标均首次合格进入到达球；后续完整的 30 秒操作验收通过全部检查。[90 秒独立分析](../reports/dual_target_control/short_waypoints_twr_20261015/validation_analysis_inbound90.json)、[最终独立分析](../reports/dual_target_control/short_waypoints_twr_20261015/validation_analysis.json)。

## 参数与使用

| 项目 | 当前配置 |
|---|---:|
| 相邻航路点三维距离 | 6～12 m |
| 整机模型质量 | 1.0 kg |
| 标称最大总推重比 | 2.5 |
| 单旋翼最大推力 | 约 6.129157 N |
| 最大总推力 | 约 24.516626 N |
| 请求速度上限 | 4 m/s |
| 规划/指令加速度限制 | 4 m/s² |
| 到达范围 / 实际偏航误差门限 | 0.5 m / 20° |

入口仍为根目录 `03_三维双目标控制.cmd`。停止飞行后，可在 Qt5 的“点间距下限/上限”中修改距离并应用。对应 [控制配置](../configs/dual_target_control.json) 的 `target_distance_min/max`；上下限均为 0 时启用全场随机方式。首点相对任务开始位置生成，下一点相对当前点生成，每次命中后以原蓝点为锚点生成新的蓝点。因此，无人机直接到蓝点的距离可能超过 12 米。

质量和推重比位于 [AirSim 设置](../configs/dual_target_airsim_settings.json) 的 `Vehicles/DroneControl/DynamicsProfile`。这是本工作区新增的扩展；修改动力配置后需结束并重启仿真。Qt5 连接后显示已核验的模型质量与标称推重比。当前没有通过 Python API 在空中修改动力的功能。

## 实现与边界处理

随机点从以锚点为中心的三维球壳与场地缓冲框的交集中生成，使用有界采样；确定性后备方法仍满足距离区间，不退回全场长距离抽样。对不可行区间明确报错；外部显式 `set_targets` 可设置更长任务。[采样实现](../python/dual_target_control/core.py)、[采样回归](../python/dual_target_control/test_waypoint_spacing.py)。

短航段实测暴露出边界目标的进点段退化：一个目标距缓冲边界仅约 2.4 mm，原先与出点段共用的约束把进点直线缩到约 17.4 mm。现将进点直线按反向可行空间独立裁剪，该记录中的进点段扩为约 3.03 m，恢复横向速度收敛；仍保留双目标联合规划和原命中门限。[回归测试](../python/dual_target_control/test_terminal_corridor.py)、[首轮诊断](../reports/dual_target_control/short_waypoints_twr_20261015/validation_analysis_first.json)。

动力扩展通过调整最大转速并重新计算旋翼推力、扭矩实现，同时按质量重算惯量。当前质量未变，惯量与原模型相同。没有选择该扩展的 GenericQuad 仍保留原始默认参数。启动后从物理模型打印 `DTC_DYNAMICS` 回执，Python 核验 settings、进程身份及新鲜日志；旧插件仅忽略新 JSON 字段时不允许起飞。[动力回执](../logs/dual_target_airsim_20261015_200705_681433/dynamics.json)、[核验实现](../python/dual_target_control/dynamics.py)。

编译命令：`scripts/build_dual_target_dynamics.ps1`。本次 AirSim 模块编译约 42.91 秒，BuildId 与 UE4.27 一致。[编译日志](../reports/dual_target_control/short_waypoints_twr_20261015/compile.log)。回执是实际加载模型的标称参数证明，不是测力标定，也不代表老师实机的完整动力参数。

## 验证结果与历史记录

最终代码的包内 **117 项测试通过**。[测试输出](../reports/dual_target_control/short_waypoints_twr_20261015/unittest_full.log)。离线滞后模型的 24 组、48 个目标腿全部首次合格命中，回追和未命中越过目标平面均为 0；该模型不含完整旋翼/姿态动力学。[离线矩阵](../reports/dual_target_control/short_waypoints_twr_20261015/offline_turning_validation.json)。

- **90 秒控制验证**：运行 [195940](../logs/dual_target_airsim_20261015_195940_290437/summary.json)，3585 条状态、19 次命中。相邻点间距约 6.0158～11.6743 m；独立球面求交核对为 19/19 首次合格命中，无回追，最大入口偏航误差约 18.24°。实际位置未越过完整场地边界，113 条状态进入缓冲区，因此不能声称轨迹完全留在缓冲框内。原操作脚本用“隐藏视图时命中计数必须不变”判队列保持，短航段下合法命中前移导致这一项失败；原始 `validation.json` 的 FALSE 保留。
- **最终 30 秒操作验证**：运行 [200705](../logs/dual_target_airsim_20261015_200705_681433/validation.json)，1360 条状态、5 次命中，24 项独立检查通过。首次合格命中 5/5，无回追；实际位置未进入缓冲区或越过完整边界。暂停减速、队列保持、UE 显示/隐藏/重开、实际跟随、原生截图、落地、解除电机使能和释放 API 控制全部通过。隐藏视图期间合法命中一次，蓝点按顺序前移为红点，没有重置任务。

最终运行保存精确 `start_state.json`，据此重放初始两点及全部随机补点，误差为 0；`dynamics_startup.log` 与动力回执中的日志 SHA 一致。[最终独立验收](../reports/dual_target_control/short_waypoints_twr_20261015/validation_analysis.json)。

另外保留 [195157 首轮运行](../logs/dual_target_airsim_20261015_195157_981361/validation.json)：19 次命中，但独立分析只有 17/19 首次通过；以及 [200424 操作验证](../logs/dual_target_airsim_20261015_200424_108779/validation.json)：控制与动力检查合格，原生截图请求恰逢隐藏视图而未导出，原始结果保留为 FALSE。最终脚本在重开视图、确认可见后再截图，最终验收有真实截图文件。

90 秒记录的规划耗时 P95 约 1.774 ms、最大 2.537 ms；实际状态间隔 P50 约 22.49 ms、P95 约 39.04 ms，仍不能声称稳定达到请求的 50 Hz。航路点序列与旧长航段任务不同，未据此声称动力升级带来了多少速度提升。更多随机种子及高速档需分别验证。[分析脚本](../reports/dual_target_control/short_waypoints_twr_20261015/validate_run.py)。
