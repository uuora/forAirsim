# 独立制动与响应测量方案

状态：`LOW_SPEED_XY_CANDIDATE_HELD_OUT_VALIDATION_COMPLETED`，2026-10-03。本文件定义 V6.2 开发重复后的工程测量门槛；各版冻结输入、开发失败与新候选独立验证分别登记。范围为 AirSim、DroneA、固定世界高度，DroneB 待命。方案由 AI 辅助整理。[当前准入路线](T1正式采数准入与后续路线.md)、[V6.2 冻结预算](../../configs/trajectory_timed_pilot_v6p2/center.json)、[当前测量冻结输入](../../configs/braking_response_v1p4/conditions.json)、[完整实测与失败](独立制动与响应实测结果.md)

## 需要核验的假设

V6.2 边界包络按 `u*h + u²/(2*a)` 留出距离，其中声明窗 `h=0.50 s`、制动模型参数 `a=0.15 m/s²`、额外位置余量 `0.02 m`。源码用同一数值限制请求速度变化。独立测量随后发现该声明在 0.06 m/s 四方向的采样停距上不足；新候选 h=1.0 s 已在两个新会话、十六个低速 XY 脉冲中验证。请求变化率与实际降速能力仍是两种量，等效窗口不等于精确执行延迟，采样验证不证明实际常数制动加速度。原 V6.2 配置保留。[包络公式及声明范围](../../python/trajectory_execution_guard.py)、[原执行器](../../python/trajectory_timed_experiment.py)、[实测范围](独立制动与响应实测结果.md)

独立任务使用预设本机速度请求和实际状态，不读取目标位置、图像或气球真值。它用于检验包络参数和控制接口；不进入效率/感知方法成功率，也不作为目标身份或遮挡结果。

## 首版执行顺序

1. **冻结测量输入与分析口径。** 沿用实际速度 0.15 m/s、加速度 0.30 m/s²、固定 Z=-3 m、高度误差 0.12 m、工作区与 0.15 m 内侧保护界。源码、配置、相机/仿真设置与会话启动记录单独存档，禁止在方法重复运行中改参数。
2. **纯接口与短验收。** 先验证零请求保持、请求变化率、时钟顺序、超限/查询失败保护以及安全收尾。每次保存全部拒绝向量；短验收不估计制动参数。
3. **低幅度脉冲。** 首版拟用 XY 请求幅度 0.03、0.06 m/s，±X、±Y 四个方向，按原 0.15 m/s² 请求变化率逐步增加和下降。保持时间不超过 1 s，回到零请求后持续查询到稳定。先完成低幅度、四方向的独立门槛，再决定是否需要更高幅度；未经测量的 0.12/0.15 m/s 范围不能沿用低速结果。
4. **独立会话按正序/反序重复当前流程。** 当前自状态减速与零目标请求共用同一包络及变化率流程，首版不把它们虚构成两个独立方法。先测现有流程，在两个独立 UE 会话中按幅度和方向正序/反序各安排八个脉冲；脉冲间稳定后重新定位。所有已派发脉冲进入分母，超时、保护和未稳定均保留。每个会话完成并复算后才启动下一个。
5. **冻结适用范围。** 依据实际入段速度、观测间隔、响应延迟和停距结果修改下一版包络或明确拒绝不支持的范围。参数改变必须新建版本并重新做方法开发验收，不能用修改后的假设回写 V6.2 的结果。

幅度、方向与判据在执行前冻结：0.03/0.06 m/s，四方向。V1.2 单独低幅度门槛通过，完整正序的模型余量检查失败，反序未开始；同一个 h=1.0 s 候选在 V1.4 的两个新会话中验证，正序先执行 0.03 再执行 0.06，独立复算后启动反序，另备的低幅度配置没有派发。原入场容差 0.006 m/s、最小幅度比例 0.7 保持；实际速度入场等待上限 3 s，要求连续合格 0.25 s，再保持 1 s。停止要求实际速度 ≤0.003 m/s、实际加速度 ≤0.02 m/s²、实际已派发 XY 请求为零，连续 0.5 s；最大查询间隔 0.25 s。零速度门槛按保存查询跨度确认，地面稳定检查在派发试次前完成。正式方法实验规模另行冻结。[配置](../../configs/braking_response_v1p4/session_forward.json)、[执行器](../../python/braking_response_experiment_v1p3.py)、[复算](../../python/analyze_braking_response.py)

## 每个脉冲必须保存

| 数据 | 用途与口径 |
|---|---|
| 请求发出/返回 host 单调时间、序号、XY 请求与固定 Z | 复算变化率和 RPC 时序；请求时长不直接当作实际作用时长 |
| 原始 AirSim 状态时间戳、查询接收时间、实际世界 p/v/a 和姿态 | 独立核验实际运动、保护界及高度；固定采样间隔不等于实际查询间隔 |
| 加速结束、降速首次请求、首次明显降速、稳定区间 | 明确测量起点；稳定条件及“明显降速”阈值在执行前冻结，不能事后选点 |
| 降速段实际最大前向位移、采样路径、初始/峰值/终末速度 | 以首次降速请求前最后一条保存的实际查询为原点，保存查询到请求的时间差；后续记录通过唯一原点查询位置判段；路径不替代最大前向位移 |
| 最大查询间隔、缺失样本、超时、拒绝及保护向量 | 标明测量覆盖不足；缺证据时不估计正面的模型能力 |
| 返航、落地、解除武装、释放 API 控制与安全关闭 | 与脉冲完成分开记，不用安全收尾覆盖脉冲失败 |

响应延迟应分别报告 host 请求到状态观测的代理时间与 AirSim 状态时间差，不能称精确执行时刻。实际加速度原始值与速度差分代理分别标记；控制代理量不能改名为真实能耗。

## 分析与停止要求

- 同一脉冲的遥测点先汇总为该脉冲指标；独立会话数量单列，不能把查询点作为独立实验。
- 根据真实查询间隔作图和积分，保留未稳定试次与未测到的停距，不以末帧强行定义停止。
- 空间边距、实际速度/加速度、姿态、高度、数据完整性任一门槛失败，停止后续脉冲并安全收尾。
- 只在已测速度、方向、姿态、设置和降速流程内检查声明模型。采样结果不是连续时间安全证明，也不能外推到现实设备。

低速测量已发现原模型偏差并完成一个候选的独立验证；更高幅度、高度方向及姿态条件仍待测量，不将本结果外推到原 0.15 m/s 上限。本项目随后继续相机姿态/三维变换、身份与可见性评分、遮挡/延迟条件及正式 T1 方案；T2、T3 仍按三项研究路线推进。[下一轮接口验收](下一轮三维与姿态接口验收计划.md)、[三项研究路线](../research-plan-20260930/AirSim三项研究执行路线.md)
