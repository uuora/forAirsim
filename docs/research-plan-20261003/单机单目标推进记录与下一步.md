## 当前实现与研究范围

已经接通：同一次请求获取 RGB/深度及各响应时间戳、实际相机与机体坐标检查、实测起点运动状态、有限候选五次多项式规划、执行前时效复核、实际状态保护以及返航落地和控制释放。[控制器](../../python/trajectory_single_experiment.py)、[规划内核](../../python/perception_trajectory_planner.py)、[时间戳感知](../../python/timestamped_target_provider.py)。

当前执行版本是 `fixed_world_height_preview`：固定世界 NED Z=-3 米，候选终点的 Z 增量为零；`moveByVelocityZAsync` 发送 XY 速度和经实测 local/world 平移换算的 Z 位置。规划输出提供正时间参考，再滚动生成短段命令。这是固定高度的 preview 接口，尚不是完整三维轨迹优化执行，也不是按多项式时间精确跟踪首段。[V3 extended 配置](../../configs/single_trajectory_fixed_height_v3_extended.json)、[执行实现](../../python/trajectory_single_experiment.py)。

效率与感知方法共享候选集合、约束和执行预算，当前主要改变图像居中代价权重。实例身份关联、身份置信校准、遮挡预测以及运动目标评价尚未完整实现；目前不能称为这些模块已齐全的感知任务方法。目标真值的 `geometry_oracle` 输入与图像/深度的 `sensor_surface_estimate` 分组登记，后者估计可见表面代表点，不能称为气球中心。[研究协议](../research-plan-20260930/AirSim三项研究执行路线.md)。

## 60 毫秒机制：源码事实与当前推断

本地 SimpleFlight 源码设置 `api_goal_timeout=60` 毫秒。在 API 已接管且 `takenoff_` 为真的情况下，若当前目标距最近更新超过该阈值，源码切换到当前位置保持模式；新的 `setGoalAndMode` 会更新目标时间并清除超时标记。[Params.hpp](../../external/AirSim/AirLib/include/vehicles/multirotor/firmwares/simple_flight/firmware/Params.hpp:136)、[OffboardApi.hpp](../../external/AirSim/AirLib/include/vehicles/multirotor/firmwares/simple_flight/firmware/OffboardApi.hpp:47)。`commandVelocityZ` 在源码中设置 XY 世界速度与 Z 世界位置控制。[SimpleFlightApi.hpp](../../external/AirSim/AirLib/include/vehicles/multirotor/firmwares/simple_flight/SimpleFlightApi.hpp:304)。

据此提出工程解释：短速度命令完成后，图像读取及规划等待可能留下超过阈值的目标更新间隔，触发保持模式，再切回移动控制时出现运动瞬态。V3 在采集和规划等待期间提交同模式的 XY/Z 维持任务，并将这些提交单独写入 `goal_keepalive_records`。每条请求时长 0.5 秒、未调用 join，可被后续任务替代；请求时长不能相加为实际飞行时间。[控制器与记录](../../python/trajectory_single_experiment.py)、[命令统计规则](../../python/analyze_trajectory_pilot.py)。

**源码机制已核对，V2 加速度异常的完整因果归因尚未证明。**当前没有逐时刻记录固件超时状态，也没有仅改变该因素的盲化或交叉复现实验；V2 拒绝查询缺失又限制了诊断。V3 已记录状态表现改善与该解释相容，但不能据此断言所有异常均由 60 毫秒机制导致，更不能声称已经消除全部未采样瞬态。

## 下一步按验收推进

1. **严格匹配实际初始状态并复现 sensor 闭环**：当前两次已达共同观察条件；下一步固定实际位置、速度、加速度和姿态的接受范围，在独立会话复现。继续检查时效、所有实际运动查询、保护理由、失败分母、落地和控制释放。保护返回与任务完成分别判断；失败照实保留。
2. **中心和左右偏移独立成对先导**：冻结同版本执行器、估计、候选、约束和预算；相同场景种子配对，方法顺序平衡，在多个独立会话重置并核验起点。先测任务达标、失锁、实际路径、求解耗时和约束违例，再据变异和运行吞吐确定正式规模。
3. **实例身份、遮挡和延迟**：加入明确的指定实例关联与独立核验；逐项增加相似干扰、目标不存在、遮挡/重获、推理或通信延迟。颜色形状分数、连续帧计数或 VLX 自报分数不得直接称为身份概率。YOLO/低频 VLX 作为单独感知条件加入，避免同时改变感知与规划而混淆归因。
4. **冻结正式任务一**：明确方法适用范围、对照/消融、场景种子、终止条件、主要指标和独立统计单位。现有路线采用关键工况至少 30 个独立回合，并在先导后结合变异与计算预算冻结；相邻帧不是独立回合。原始 RGB/深度、目标估计、候选代价/拒绝、参考与实际轨迹、全部已开始回合及失败/中断都可复算。
5. **平面接口与 3D 研究分版本**：当前可以先评价固定高度受限方法，章节结论应明示边界。完整三维研究另需 Z 向候选、三维轨迹到执行器映射、姿态处理及实际跟踪/共同约束验证；不能将本批固定高度 preview 数据包装成完整 3D 优化结果。
6. **任务二准入**：任务一 sensor 估计轨迹闭环通过后，再做双机同时观测、坐标与时间统一、共享观测及互补轨迹；加入机间距离、消息时效和请求/就绪/提交交接协议。旧顺序补位仍只作为基线。
7. **任务三准入**：任务二联合规划与 generation 协议通过后，把“一次仅一个气球、有效接触后两机取消保持、刷新、重新观测与分配”接入实际仿真。先稳定 3 轮连续规则会话，复查后再扩到冻结的 10 轮或时限。规则刷新裁判与连续闭环稳定后，才进入固定奖励协作学习和独立测试；合成状态机重放不计作接触飞行数据。

上述次序依据[任务登记与准入配置](../../configs/thesis_simulation_tasks.json)及[执行路线](../research-plan-20260930/AirSim三项研究执行路线.md)。每一步以可复查验收为前提，不承诺毕业或论文完成日期；论文方法与结果范围应与对应版本实际证据一致。
