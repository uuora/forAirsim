# 研究内容一控制仿真：现有模块与待补接口

日期：2026-10-29。状态：依据当前代码的接口核对与实施设计。AI 辅助完成。

本清单对应[详细实验任务书](研究内容一_控制仿真实验设计_20261029.md)和[导师汇报稿](研究内容一_导师汇报一页稿_20261029.md)。核对范围为下列源文件；本文没有运行搜索、AirSim 或新的性能比较。统一接口在本文中是**设计协议**，不能视为已经实现。

本轮最小验证的后端为三维一阶速度滞后质点，固定速度指令跟踪器。它可核验时序参考、跟踪误差和指令限幅，不提供姿态、电机、推力或实机飞行证据。MVP 的逐轨迹结果及执行数量应由实际运行日志确认，不能由方案数量代替完成记录。

## 2. 统一 `evaluate_candidate` 协议（待实现）

建议把优化器、曲线构造、执行后端和评价规则解耦。以下是接口意图，不是当前可导入函数：

```python
evaluate_candidate(
    parameters, *, family, representation, boundary,
    scene, controller, plant, initial_state, disturbance,
    backend, run_context, deadline_host_s=None, include_trace=False,
) -> CandidateEvaluation
```

`backend` 先实现 `lagged_point_mass`，再实现 `airsim_3d_velocity`。不要在模块导入失败时悄悄回退到另一后端。控制器配置在同一对比任务内固定，优化器只接触声明的曲线参数。

### 输入必须绑定的内容

| 输入 | 最低字段及要求 |
|---|---|
| 候选与参考 | 候选 ID、参数单位/顺序、规范参数域、family、representation、T、起终 p/v/a；拒绝越界和非有限值；改变 T 时重建保持物理端状态的基线 |
| 场景 | 坐标系、工作空间、障碍几何、机体包络及安全余量；开发/留出标签和场景版本。当前 `_layout` 及固定场景可先适配，通用新场景不得被字符串默认值替代 |
| 固定控制器 | 位置增益、速度与变化率限制、参考时钟、目标采样间隔、末端处理；限幅次序明确 |
| 模型与初态 | 模型版本、tau/积分法；实际 p0、v0、上一指令和可复位内部状态。简化模型默认初态是 q(0)、qdot(0)、qdot(0)，位置偏差实验只改变实际 p0 |
| 扰动 | 类型、坐标轴、幅值/单位、绝对开始/结束时刻、随机种子、延迟队列初值；无扰动也显式记录 |
| 上下文与预算 | run/task/seed/candidate ID、代码/配置摘要、后端证据、计时起点、截止时刻及重试规则。缓存 context 还须绑定所有影响输出的条件和评价器版本 |

当前 `evaluate_timed_parameters` 没有上述全部入口：新增适配器应显式检查兼容范围，不能把自定义 `BoundaryStates` 传给曲线后，仍使用只适用于默认端状态的闭式质量下界。

### 输出与异常必须区分

统一记录建议包含：

- `status`：完整评价用 `EVALUATED`，可行与不可行均是已完成评价；其余可用 `PRUNED`、`INIT_FAILED`、`EXEC_FAILED`、`DEADLINE`、`DATA_INVALID`。
- `score`、`quality_term`、`feasible`：完整评价的 score 有限、feasible 为布尔值；未完整评价时相应字段为 null。`PRUNED` 仅保留有依据的下界、阈值和跳过原因，不能填入虚构分数。
- `checks` 与 `failure_reasons`：约束失败、初始化失败、接口异常、数据质量失败分别计数；旧搜索接口对目标异常直接报错，适配时应预先决定终止/恢复规则，不能默默用好分数替代。
- `metrics`：T、参考 jerk 能量、同步 RMSE、采样峰值、T 时刻终端 p/v 误差、速度及变化率限幅时间比例、实际路径净空及其判定范围。
- `counts`：提案、完整评价、部分评价、廉价筛选、缓存命中、额外验证分别记录；同时保存源评价 ID，避免将缓存命中称为新 rollout。
- `timing`：准备/初始化、参考与几何检查、控制执行、诊断与约束检查、最终验证、总墙钟和 CPU 时间；记录嵌套关系，不能把互相包含的时段相加为总耗时。
- `provenance`：源与配置摘要、后端和模型、完整初态、条件、指标定义、评价完成时刻、trace 路径、证据范围。

可复用现有搜索要求的 `score`/`feasible`/`score_details` 映射，但完整协议的状态、计时与异常适配还需要单独实现。

## 3. 最小控制验证与正式墙钟运行器

### 本轮 MVP 可用部分

直接调用 `curve_from_parameters` 和 `run_timed_tracking`，按固定参数产生三类参考、两档时长；每个参考分别运行名义、初始 y 偏差 +0.20 m、−0.20 m 和 tau=0.45 s。每次调用创建独立状态，保存 N+1 个参考/实际状态以及 N 个保持指令区间。它适合验证 E0 和初步 E4，不需要先启动 ABOM。

MVP 中如仅检查采样峰值 ≤0.5 m、终端位置 ≤0.25 m、终端速度 ≤0.5 m/s，应将结果命名为“控制误差判据通过”，不能称为含障碍与实体机体的完整可行性。直线参考不绕障的结果也不能放进障碍场景当作安全执行。

独立核查应从日志重算：时间单调与 T、相同 t 的参考值、初态、误差与梯形 RMSE、速度/变化率限制、每个 ZOH 步的 p/v 更新、门槛、配置及源文件摘要。图表和序列化耗时不混入模型执行时间，端点非零参考速度不被额外悬停替换。

### 墙钟预算运行器：待实现

现有 `run_search`、`run_blackbox_search`、`run_screened_search`、`run_feedback_search` 的 budget 都是评价/提案数量。不能仅在它们运行完后比较 elapsed_s，就宣称做了固定墙钟预算搜索。[搜索](../../python/trajectory_research/search.py)、[坐标对照](../../python/trajectory_research/blackbox.py)、[筛选](../../python/trajectory_research/screened_search.py)、[反馈](../../python/trajectory_research/feedback_search.py)

需要新增统一调度器：

1. 在规定的冷启动或持续服务条件下设单调时钟起点和时限，绑定所有方法相同的初态、初始候选与配置。
2. 每个候选记录开始、完整评价完成、必要验证完成及可输出时刻；网络生成/训练和初始化同样消耗预算。
3. 仅把在截止前完成必需验证的可行候选纳入该预算成果。超时跨界候选另记，不将之后获得的分数回填较早截点。
4. 保存 incumbent 随完成时刻变化的事件流。策略与最终预算无关时，可读取多个合法时限截点；依赖剩余预算时，各预算独立运行。
5. 若后端暂不支持中断，记录实际超时量并返回先前完成的可行解；这一实现不构成硬实时保证。
6. 预设质量要求，保存预算内未达标项；达标时间使用含右删失的分布及达标比例，不能只平均成功运行。

还需修正计时解释：[run_timed_feedback_research.py](../../python/run_timed_feedback_research.py) 的 `wall_s` 在搜索返回后即停止，选中解重查和另外两个模型条件验证随后执行。这是已明确边界的搜索计时，不能直接称为“含最终验证的可输出轨迹规划时延”。新运行器应分别计入必需输出验证与预算外独立测试；图表和论文统计留在计时外。

## 4. AirSim 三维研究执行器

待新增独立 `airsim_3d_velocity` 适配器，复用连接、NED 转换和时间戳记录模式，解除旧感知计划、XY 速度和固定高度的耦合。可复用入口见 [runtime.py](../../python/dual_target_control/runtime.py)、[既有时序执行](../../python/trajectory_timed_experiment.py)及[时序参考](../../python/trajectory_timed_reference.py)。

| 环节 | 待补内容 | 验证要求 |
|---|---|---|
| 后端确认 | 记录车辆、设置、物理后端、SimpleFlight 配置和启动证据；可用时核对本项目动力学回执 | 实际连接与 receipt 一致；缺失则如实标识，不能由历史日志替代当前证据 |
| 初始状态 | 每候选统一 reset、控制权限、解锁、准备位置、预加速至要求初速；固定 yaw 与内部历史重置方式 | 达到冻结的位置/速度容差才启动参考，有限重试、完整记录；准备与失败重试计入开销 |
| 时间轴 | 选定仿真状态时钟推进参考，或另做主机时钟实时实验；同时保存两者 | 明确 t0 和来源；禁止循环编号×0.02 s 冒充实际经过时间，禁止混用时钟 |
| 指令 | 用同一控制式生成三维世界速度，显式转换 NED，再发送 `moveByVelocityAsync` | 保存原始、速度限幅、变化率限幅及实际发送指令；发送 ID 与状态采样 ID 可关联 |
| 原始日志 | 查询请求/返回主机时刻、状态 timestamp、参考时刻、p/v/姿态、指令请求/返回、碰撞及异常 | 同行状态通常先查询、后发送指令，不将该状态当成此指令已产生的响应 |
| 终态 | 在参考 T 对应状态计算终端误差；预先规定插值与最大间隔规则 | 日志跨 T 时有合法对齐；缺测或大间隙记数据质量失败 |
| 退出 | T 后统一接管/减速/落地或移交，另记阶段 | 不用额外悬停后的低误差替代 T 处误差；RPC 完成不等于执行器终止 |
| 评价 | 共享指标定义，实体净空和碰撞依据单列 | 采样点检查、仿真碰撞事件和连续路径充分条件分别说明，不互相替代 |

先选预先规定的少数参考在 AirSim 重放，检验接口与模型迁移，再决定昂贵搜索规模。仅重放最终轨迹支持执行复核；若要证明减少 AirSim 黑箱调用，必须实际把 AirSim 作为评价后端开展配对预算实验。暂停仿真后执行昂贵搜索可用于离线规划，实时部署能力另需连续时钟证据。

## 5. 扰动和诊断机制的接口缺口

| 项目 | 当前状态 | 最小实现与检查 |
|---|---|---|
| 初始位置偏差 | 下层支持，完整目标包装尚未接入 | 向真实初态 p 添加偏差，参考边界、v0、上一指令保持固定；评价和上下文均记录偏差 |
| 响应失配 | 下层及完整目标均可设 `TrackingCondition.velocity_lag_s` | 固定选中轨迹后改变 tau，单独评价；测试反馈不进入搜索；不要把代理 tau 当作物理电机参数 |
| 初始速度偏差 | 当前下层缺少入口 | 显式增加真实 v0 与上一指令规则；必须保持参考不变，更新速度包络假设并加入解析检查 |
| 外部加速度脉冲 | 待实现 | 加在真实速度动力学，使用绝对时间 `[1.5,2.0]` s、固定幅值与符号；步进遇到脉冲边缘时分割积分区间，核对冲量，不改参考轨迹冒充外力 |
| 指令延迟 | 待实现 | 显式命令队列，固定如 40 ms、初始填充上一指令；保存生成/计划生效时刻，必要时拆分区间；不把查询 RPC 延迟自动当作物理命令延迟 |
| 测量噪声 | 待实现 | 将带噪观测传给控制器，保留无噪真实状态用于评价，绑定随机种子和噪声过程 |
| 筛选+诊断 | 两个独立搜索接口，整合待实现 | 同一循环维护候选、父代、诊断和筛选阈值；只用真实完整评价的诊断更新网络；PRUNED 项不能伪造诊断。以匹配无筛选版本回放保留集、候选流和训练输入 |

增加外力后，原来的“速度是初速与限幅保持指令的凸组合”前提会改变。[actual_nominal_path_checks](../../python/trajectory_research/timed_control_task.py) 的采样间隙净空界不能原样套用；须推导含扰动的速度上界或返回判定未解决。即使采样速度仍低于上限，也不能据此证明采样间隙内的界成立。命令延迟同样须使用实际生效的分段保持指令与真实区间做检查。

## 6. 建议实施优先级与交付检查

| 优先级 | 任务 | 通过后再开展 |
|---|---|---|
| P0 | 复用现有下层做固定参考 MVP；冻结配置、源码、完整 trace、汇总和图；独立核查同步误差与积分 | 为 E0 提供实际运行证据，并确认失败工况原因 |
| P1 | 统一候选评价协议；补位置偏差包装、状态/计时账本、必要最终验证口径 | E1 闭环评价与几何评价的公平比较 |
| P1 | 墙钟截止调度器及可输出时刻记录；冷/热条件分开，所有方法同预算 | E2 正式效率主实验 |
| P1 | AirSim 三维独立执行器、可复位初态、双时钟和终端对齐 | 少量预先指定轨迹的 AirSim 复核 |
| P2 | 新留出场景接口、随机种子/环境冻结、失败分类、配对统计 | 跨任务正式对比，当前开发场景不再称未见测试 |
| P2 | 外力、延迟及相应路径判据；按开发结果决定是否整合筛选与诊断 | 扩展 E3/E4；现有诊断分支优势仍须检验 |
| P3 | 七维/多段/偏航，以及确有必要的更完整控制与实体模型 | 在前述闭环和预算证据成立后扩展研究范围 |

交付时按“已有代码—本轮实际运行—待实现—待验证假设”列状态。任何模块的存在、单元测试通过或历史日志，都不能替代本轮 AirSim 运行结果；控制接口核验通过也不等于 ABOM 提效已经成立。
