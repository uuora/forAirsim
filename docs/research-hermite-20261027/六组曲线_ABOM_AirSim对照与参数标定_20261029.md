# 六组曲线与ABOM对照：AirSim执行和参数标定

日期：2026-10-29。状态：在已有控制实验上增加六组先导；具体完成情况以运行记录为准。AI辅助完成方案、代码核查与解释。

## 1. 六组可以怎样比较

| 组ID | 曲线表达 | 参数生成 | 回答的问题 |
|---|---|---|---|
| B0 | Bézier | 规定的初始参考，无搜索 | 初始参考的控制表现 |
| H0 | Hermite | 同一规定参考，无搜索 | 表达实现是否一致 |
| B1 | Bézier | 基础ABOM网络适配器 | 搜索能否改进初始参考 |
| H1 | Hermite | 同一基础ABOM配置 | 同一搜索空间下的表达核验 |
| B2 | Bézier | 改进ABOM候选分支 | 新机制是否有增益 |
| H2 | Hermite | 同一改进ABOM候选分支 | 新机制与表达的交互 |

六组固定同一跟踪控制器、起终状态、参数域、候选预算和评价规则。普通组没有搜索调用，其运行成本和执行质量单列，不能给普通组虚构迭代次数。

当前 `single_bump` 使用同一规范参数 `(dx,dy,dz,T)`。Bézier与Hermite在这个空间中是同一轨迹的两种表达；普通组可能完全重合，优化组也可能输出相同轨迹。这是公平核验，不应人为制造差异。若另比较三次Bézier与五次Hermite，应单列为结构实验并披露阶数、端状态约束和自由度的差异，不能将所有效果都归因于曲线名称。[L1]

## 2. 首轮运行范围与正式实验

首轮采用“简化闭环模型搜索，AirSim统一执行最终参考”。它回答输出轨迹在AirSim中的跟踪表现；搜索调用仍属于简化模型，不能称为直接由AirSim反馈优化，更不能用其耗时证明减少了AirSim搜索调用。

首轮先导固定：central开发布局、四维参数、种子1101；基础和改进分支共用 `N=20`、80候选、dropout=.95、源码式学习率1e-3、均匀初始候选和同一锚点。每个优化组80次搜索评价及1次选定结果复核；普通组仅1次复核。因此为320次搜索评价+6次输出复核，不含后续AirSim执行。

本轮可运行的“改进候选”采用现有 `abom_perturb`：以成对参数扰动替换每代50%的神经候选，初始归一化扰动尺度0.15，随成功比例调整，限于[0.025,0.5]。它仍通过端状态保持的曲线解码器生成参考。为了区分扰动的作用，首轮关闭廉价筛选；未把调低dropout混入新机制。50%与尺度是预先规定的先导选择，没有证据证明它们最优。[L2]

同一原文网络及源码式适配器并不等于原论文完整复现：本地实现的均匀初始化、SmoothL1对重复最好个体学习、每代重建AdamW，与论文算法描述存在差异。报告以“基础ABOM网络适配器”和“改进候选”命名。[S1,L2]

六条参考写入统一 `airsim_replay_plan.json`，随后由独立单机仿真执行，采用专用端口，保存源码、配置、真实状态时间戳、主机查询/发送时间、参考与实际p/v、原始/限幅指令、碰撞和异常。

AirSim首轮使用空地图，只验证跟踪和执行接口；简化模型central障碍并未因此自动出现在AirSim中。若未创建并核验相同障碍布局，净空指标必须标记不可用，不能将无碰撞当作复杂环境避障能力。后续正式对比再建立匹配场景。

正式阶段建议使用新场景、多个优化种子和独立执行重复，六组交错顺序；每个方法都执行其预先指定种子的输出，不只挑最好轨迹。首先按可输出/可执行判据比较，再报告质量。增加随机、高斯或坐标搜索作为辅助强基线，检验网络开销是否值得。

## 3. ABOM参数分成三类

**轨迹变量 x**：`dx,dy,dz,T`，由搜索器生成。三维飞行并不表示搜索维数为3；当前 `d=4`。每次改变T须重新构造满足物理起终状态的参考。

**网络权重 θ**：由固定规则初始化，在当前搜索过程中用优良样本在线更新，不由人工逐项指定，也不等于底层控制器增益。

**超参数**：种群、学习率、dropout、网络尺寸、更新频率、评价预算等，需要依据原文和开发实验确定。

| 超参数 | 原论文设置/依据 | 首轮使用和解释 |
|---|---|---|
| 种群N | 20，Appendix G及§4.4 | 20，80候选可整除；本地旧默认16另行披露 |
| 学习率η | AdamW 1e-3，Table5 | 固定1e-3；当前适配器硬编码，不虚构已做lr搜索 |
| 交叉/变异dropout | pC=pM=.95，Table5 | 首轮共同.95；这是丢弃概率95%，不是保留95% |
| 注意力维数dA | d，Table5 | 4，因为优化参数共4个 |
| MLP隐层dM | 2^floor(log2 d)，Table5 | 4；扩为7维时该公式仍给4 |
| 更新频率 | 搜索过程中在线更新 | 当前适配器每代一次更新 |
| 网络层数 | Table5没有给出这一行 | 当前适配器1层，属于实现选择 |
| 权重衰减 | Table5没有给出这一行 | 当前源码式适配器1e-5，属于实现选择 |
| 评价预算 | 论文任务有其专用预算 | 本先导80，计入初始20个候选，后续3代；不直接套论文高维预算 |

原论文的敏感性分析主要在30维BBOB上开展，不能据此认为其参数是当前四维控制问题的最优值。[S1]

当前接口要求整代预算：`FE = N × (1 + G)`，G为初始种群之后的子代数。N=20、FE=80对应3个子代；N=16、FE=128对应7个子代。比较种群时应固定总评价预算，例如160同时被16和20整除，分别有9与7个子代；不能同时固定N不同、代数相同，却声称评价预算相同。

## 4. 怎样确定正式使用的参数

1. **保留论文默认参考。** 先运行默认值验证接口；正式“基础ABOM”与“改进ABOM”必须共用同等调参机会，不能只给改进组挑最优参数。
2. **先调最少的项。** 固定dA、dM、学习率和控制器，只在已有三个开发布局比较dropout `{0.1,0.5,0.95}`，每设置三个事前固定的新种子，N=16、128候选，共27次搜索。评价按可行输出优先、配对轨迹质量其次，并记录总开销。已有几何任务的dropout结果只能提供候选值，不能当作AirSim最优参数。
3. **再检查种群。** 如需要，在相同开发集以160候选比较N=16/20，其他设置固定；均计入初始种群。若只做很小先导，直接固定N=20并披露未完成种群标定也可以，不能称全参数最优。
4. **用少量开发用AirSim核查排序。** 模型上优选的若干配置在AirSim开发场景验证输出轨迹。若修改了配置，该场景就属于开发集，不能再当留出测试。
5. **冻结后测试。** 记录选择规则、配置、代码hash、总标定调用和成本；在新场景/种子上不再调参。测试集比较基础与改进机制，共用最终超参数。

学习率若后续确需校准，可在显式开放配置后比较 `{3e-4,1e-3,3e-3}`，额外计算单列；当前代码未开放该入口时不写成已实现。调参结果须结合可行性、配对质量与时间，不能只选某个最低单次分数或某一个有利种子。

## 5. AirSim收集的指标

| 类别 | 指标和口径 |
|---|---|
| 搜索资源 | 搜索墙钟时间、选定结果验证时间、合计输出规划时间、CPU时间、实际完整/部分评价次数、网络生成/更新开销；指出评价后端 |
| 参考质量 | T、参考jerk平方积分、参考峰值速度/加速度；单列综合目标分项 |
| 实际跟踪 | 同步位置RMSE、峰值误差、终端位置/速度误差、实际飞行时间；按真实状态时钟对齐 |
| 执行约束 | 原始与限幅速度指令、限幅时间比例、碰撞状态；姿态可记录但不假称已测电机饱和 |
| 任务表现 | 规划无输出、初始化失败、日志不合格、执行不可行、执行可行分别统计；空图不报告障碍净空 |
| 系统时序 | 状态时间戳、查询/发送/返回主机时间、实际间隔、超期与终端插值情况；不以RPC返回时间代替状态时刻 |

给定T的终端指标在T对应状态计算，随后刹停/落地单列。暂停—推进仿真属于离线验证，不能从暂停期间的充足计算时间推断实时控制能力。[S2]
