# 六组控制实验：结果量化与对比表规范

2026-10-30。用于把"跑完之后怎么读"变成可重复的表格。当前所有结果仍是开发阶段先导，本规范规定的是**正式实验**该怎么组织数据，不是对现有结果的升级。

## 1. 现有记录能回答什么

每个格子只有 1 条执行记录。它只能回答"这一次在什么条件下飞成什么样"，不能回答"哪种方法更好"：

- 组间差异和执行内的时序抖动、初始化差异混在一起，无法分离；
- 同一条参考轨迹换基（Bézier/Hermite）本来就表示同一物理曲线，单次差异没有意义；
- 没有重复就没有离散度，任何"更优"的表述都缺少分母。

## 2. 三层重复结构

正式实验的统计单位不是"一次飞行"，而是三层嵌套：

| 层 | 单位 | 控制的是什么 | 建议数量 |
|---|---|---|---|
| 目标层 | 一个冻结的三维目标方案 | 任务难度、几何 | 6 个预冻结新目标 |
| 优化种子层 | 一次搜索的随机初始化 | 搜索随机性 | 5 个配对种子 |
| 执行重复层 | 同一方案的再次回放 | AirSim 时序抖动、初始化 | 2 次 |

**配对原则：** 六组必须共用同一目标；四个优化组共用同一份种子清单。目标在调参阶段用过的，就必须进入开发集，不能再算留出测试。

## 3. 2×3 因子结构

六组不是六个并列方法，是一个两因子设计：

|  | 普通（无搜索） | 基础ABOM | 改进候选 |
|---|---|---|---|
| **Bézier** | B0 | B1 | B2 |
| **Hermite** | H0 | H1 | H2 |

- **主效应（行）**：曲线表达。B/H 在同一 `(dx,dy,dz,T)` 空间可表示同一条曲线，预期无差异；这是**实现一致性检查**，不是创新点。
- **主效应（列）**：参数生成策略。普通组没有搜索，它提供"初始参考"的参照水平。
- **交互**：改进机制是否只在某一种表达下起作用。

因此 B0–H0 的配对差应当接近 0。如果显著不为 0，先怀疑实现或时序，而不是去解释成方法差异。

## 4. 指标口径

| 类别 | 指标 | 说明 |
|---|---|---|
| 完整性 | 流程完成 / 有效完成 / 门槛通过 / 执行失败 / 数据质量失败 / 未运行 | 分开统计，不互相替代 |
| 质量 | 终端位置误差、峰值位置误差、同步RMSE、终端速度误差 | 由 `states.csv` 独立重算 |
| 时间 | 参考时长 T | 曲线自带的飞行时长，**不是**规划耗时 |
| 综合 | 综合分 `quality_term` | 越小越好，必须和质量、T 一起读 |
| 资源 | 规划墙钟、完整模型调用数、执行墙钟、限幅时间比例 | 规划来自冻结的简化模型，不是 AirSim 在线搜索 |

**限幅比例不叫电机饱和**；**T 不是墙钟**；**空地图不报净空**。

## 5. 四张表

由两个脚本产出，全部只读已有记录：

1. `compare_airsim_curve_runs.py` — 逐条核验并生成单批次对比（`comparison.csv` / `comparison.md`）。
2. `summarize_control_experiment.py` — 把多个批次汇总成实验表（`summary.md` / `cells.csv` / `provenance.json`）。

| 表 | 内容 | 回答的问题 |
|---|---|---|
| 表1 完整性 | 预定槽位、完成、有效、门槛通过、各类失败 | 实验跑成了没有 |
| 表2 质量 | 各指标中位数 [Q1, Q3] | 各组表现如何、离散度多大 |
| 表3 配对差 | 左组−右组的中位差与优/平/劣计数 | 两组的差异方向和稳定性 |
| 表4 资源 | 规划墙钟、模型调用、执行墙钟、限幅比例 | 代价是多少 |

## 6. 统计边界

- **n=1**：只描述这一次，不比较、不排名、不说"更优"。
- **n<5**：不报置信区间、不报 p 值。表3 只给中位差和符号计数。
- **n≥3**：可以有意义地报四分位区间。
- **复制证据**：同一原始证据的再次比较，`duplicate_evidence_of` 会标出，**不算独立重复**。
- **跨批次**：条件指纹不同的批次可以并列汇总，但不做合并显著性判断；一旦合并就必须先说明指纹差异。
- 所有分析都是**描述性**的，不做因果归因。

## 7. 完整跑法

以下命令都在仓库根目录 `D:\forAirsim` 下执行，解释器统一用 `.venv/python.exe`。

### 7.1 一次性准备

```bash
./.venv/python.exe scripts/prepare_abom_research.py --check-only
```

确认固定上游网络与 03 地图资源齐全；同时确认端口 **41461 空闲**，启动器遇到已占用会直接拒绝。

### 7.2 生成方案（不飞行）

**推荐用面板生成**：双击 `打开轨迹实验面板.cmd` → “固定目标生成方案”或“生成随机目标”。产物同时包含 `airsim_replay_plan.json` 和配套的 `airsim_config.json`，两者里的 `target_scene.boundary` 一致。

命令行也能生成：

```bash
./.venv/python.exe python/control_target_experiments.py --output reports/control_target_plans_20261101_t1 --seed 1101 --goal 8 0 5
```

- `--goal x y 高度`，约束 `x∈[2,12]`、`|y|≤6`、`高度∈[2,10]`；省略则按种子生成 6–10 米目标。
- `--seed` 同时决定目标（省略 `--goal` 时）和搜索随机性。
- `--budget` 默认 80，即每组 80 候选。
- 产物：`reports/control_target_plans_.../airsim_replay_plan.json`（六组方案）、`config.json`、`completion.json`、`rows.json`。
- **注意：命令行生成不写 `airsim_config.json`。** 仓库里的 `configs/curve_abom_airsim_control_targets_v12.json` 带一个固定的 `target_scene.boundary`；新目标若与它不一致，飞行会在 `target scene does not match frozen plan boundaries` 处直接拒绝。所以命令行路线需要自己准备一份 `target_scene` 匹配的配置，或改用面板生成。
- 这一步不连接 AirSim、不飞行，耗时来自 326 次完整简化模型调用。

### 7.3 跑六组（会飞行）

```bash
powershell -ExecutionPolicy Bypass -File scripts/run-airsim-curve-replay-pilot.ps1 -Plans reports/control_target_plans_20261101_t1/airsim_replay_plan.json -Config reports/control_target_plans_20261101_t1/airsim_config.json -AllGroups -ShowWindow
```

- **`-Config` 必须指向同一个方案包**，否则 `target_scene` 与方案边界不一致会被拒绝。省略 `-Config` 时启动器会用仓库里的默认配置（固定旧目标），这是最常见的失败原因。
- `-ExecutionPolicy Bypass` 不能省：本机 `LocalMachine` 执行策略是 `Restricted`，否则 PowerShell 直接拒绝加载脚本。
- 启动器自己拉起 UE、等待 41461、跑地面探针，然后逐组回放，结束时关闭自己启动的实例。
- 加 `-ShowWindow` 才看得到画面；不加走 `NoDisplay`，更快。
- 单组把 `-AllGroups` 换成 `-Groups hermite_abom`。
- 端口 41461 独占，多个目标必须**一条一条**跑，不能并行。
- 产物：`reports/airsim_curve_replay_pilot_<时间戳>/replay/`，含每组 `report.json`、`states.csv`、`trace.json`、`events.jsonl`，以及 `rows.json`、`metrics.csv`、三张图。
- 六组约 90–155 秒（含每组 8 秒展示停留，可用 `final_display_hold_s` 调小）。

也可以走面板：双击 `03_三维双目标控制.cmd` → “六组控制实验：固定/随机目标” → 生成方案 → 选择方法飞行。

### 7.4 审计

```bash
./.venv/python.exe python/audit_airsim_curve_replay_pilot.py reports/airsim_curve_replay_pilot_<时间戳>
```

PASS 只代表记录一致（哈希、时间戳、独立重算），不代表门槛通过或物理真值。

### 7.5 对比单批次

```bash
./.venv/python.exe python/compare_airsim_curve_runs.py --runs reports/airsim_curve_replay_pilot_<时间戳> --output reports/t1_comparison
```

一个方案包对应一个对比目录。不同种子或不同目标属于不同条件指纹，**不能放进同一个对比目录**。

### 7.6 汇总多批次出表

```bash
./.venv/python.exe python/summarize_control_experiment.py reports/t1_comparison reports/t2_comparison reports/t3_comparison --output reports/experiment_summary_20261101
```

汇总器会拒绝内含多个条件指纹的单个批次，并在 `provenance.json` 里记录每个批次的路径与指纹。

### 7.7 一轮最小正式实验的清单

三个目标 × 一个种子，共 3 个方案包：重复 7.2 → 7.3 → 7.5 三次，最后 7.6 一次。若加种子，每个（目标, 种子）组合各自一个方案包与一个对比目录，汇总时全部列进 7.6。

## 8. 推荐的最小正式实验

先做一个能出表、又不至于失控的版本：

- 6 个预冻结新目标 × 3 个配对种子 × 1 次执行 = 18 格/组，六组共 108 条；
- 六组在**同一目标上**交错执行，顺序记录在案；
- 分析用表1–表4，报告只写"在当前目标集和种子集上"的描述性结论。

如果要做执行重复，再加一层 ×2，并把执行重复的方差单独报告，不要和种子方差混在一起。

## 9. 不能写进论文的表述

- "某方法整体优于另一方法"——除非表3 的配对差方向在多数格子上一致，且说明了样本量。
- "换用 Hermite 带来提升"——B/H 可精确换基，差异来自实现与时序。
- "ABOM 搜索更快"——规划墙钟来自简化模型离线搜索，且当前是等候选数对照。
- "已通过真实飞行验证"——所有结论限于 AirSim 回放，且每格样本极少。
