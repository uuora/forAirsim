# 海事实验第一步：简化场景与两路图像采集

> 2026-09-15：本文保留 V1 记录。根目录启动入口已升级为船模、动态海面与气球的 V2 场景，当前使用方法见 [海事船模与动态海面说明](海事船模与动态海面_使用说明.md)。下文旧夹具流程不再是根目录启动器的行为。

本阶段已实现一个独立的海事视觉夹具（fixture），用于确认Unreal/AirSim能够放置研究对象并保存图像。它不调用旧任务控制器，不发出飞行、接触、跟踪或接力指令。

## 启动

双击项目根目录的 `Run-Maritime-Scene.cmd`，或执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\forAirsim\scripts\start-maritime-scene.ps1" -ShowWindow
```

需要DroneA、DroneB已着陆且没有活动API控制；不满足时脚本会停止，不重置或结束已有任务。运行日志打印本次输出目录，位于 `D:\forAirsim\logs\maritime_<时间戳>\`。

运行时对象不会永久保存进Unreal地图；重启场景后重跑即可。相同配置重复运行更新同名前缀对象。改变对象列表删除条目时，旧对象不会自动删除，应重启场景后运行，以免混入旧对象。

## 本版对象

| 对象 | 当前类型 | 研究边界 |
|---|---|---|
| 小型船 | vessel | 简化船壳、甲板、驾驶室与桅杆，没有船舶动力学 |
| 救生圈 | lifebuoy | 基础几何体组合 |
| 漂浮物资箱 | floating_supply | 单一示意模型，不代表全部物资类别 |
| 穿救生衣假人 | person_proxy | 假人占位模型，不是训练有效性经过验证的落水人员素材 |
| 漂浮残骸 | floating_debris | 支持后续发现与报告任务；不代表水下探测或实际打捞能力 |

使用当前Unreal工程自带基本形状构造，不下载第三方模型。后续素材公开/分发仍应按所用引擎与资产许可核对。本版纹理由代码生成纯色图片。

## 输出与证据诚实性

- `view_a.png`、`view_b.png`：两路原始RGB预览。
- `overview.png`：带“staged camera / NOT detector output”提示的并排图。
- `scene_report.json`：对象定义、分割ID、相机配置、图像尺寸、恢复结果和错误状态。
- `textures/`：本次用于着色的图片，运行时需要它们。

分割ID与类别来自人为定义的场景，属于仿真标注，不是神经网络预测。本阶段的 `detection_status` 与 `localization_status` 均为 `NOT_RUN`。脚本PASS仅表示场景创建、姿态/尺度/分割ID核验及图像采集通过。

相机临时移到位于原场景上方的独立采集区域，两架无人机保持着陆；采集完成或失败后恢复相机。两路图像顺序采集，不是经验证的同步双目，也不能作为双机实际飞行定位实验。

蓝色平面只是视觉水面背景，没有波浪、水动力或经标定海况。简化模型和色彩有很强的域差异，不宜直接据此宣称真实图像识别有效。

## 下一步顺序

1. 明确标签：落水人员、船舶、救生设备、漂浮物资和残骸，区分“对象类别”和“搜救/打捞信息任务”。
2. 选择具备清晰许可与标注的真实图像来源，先做预训练模型基线。对占位图像和真实图像分别报告，不混成一个准确率。
3. 建立少量人工审核的语言任务样本：描述观察、区分类别、提示不确定信息、引用报告证据。先测现成模型，再决定微调与RAG。
4. 冻结独立测试集后开展微调与检索对照；跨视角定位不作为本阶段默认交付。
