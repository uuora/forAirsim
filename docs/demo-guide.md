# 气球双机演示操作说明

## 最简单的运行方法

在项目目录双击 `Run-Balloon-Demo.cmd`，输入选择：

双击入口直接使用项目自带的 Python，不依赖 PowerShell 脚本执行策略。若旧窗口显示“禁止运行脚本 / PSSecurityException”，关闭旧窗口，重新双击更新后的入口即可，无需管理员权限或更改系统策略。

- `1`：A 接触气球，B 等待，然后两机返回降落。
- `2`：A 按预设路线偏离气球，退出通道后 B 补位接触，然后两机返回降落。
- `3`：双机起飞到观察位置，暂停后进行摄像头识别对照，并打开结果图。此模式结束时仍在空中、仿真暂停，不会降落或碰撞气球。
- `4`：直接打开独立的双相机监视器，左侧显示 DroneA、右侧显示 DroneB 的 `front_center` 画面；按 Q 或 Esc 关闭。

选项 1 和 2 现在会自动同时打开实时双相机窗口，飞行、补位、命中和降落期间持续刷新；在相机窗口按 Q/Esc 只会关闭画面，不会取消任务。选项 3 会先执行双机观察飞行，再做相机有/无目标识别对照，最后暂停在空中；选项 4 不飞行，只恢复气球并打开实时相机监视器。1 或 2 完成后可以继续选 3 或 4；4 会先重新创建气球，3 会重新执行观察飞行。选项 1/2 运行中不要再启动第二个任务，等它结束并暂停后再运行下一项。

相机监视器启动时会把镜头放到机体前方约 1 米、略微抬高，避免旋翼架挡住画面。A 接近气球时气球会占满画面，这是距离很近的正常透视效果；B 仍可能只看到气球边缘。

实时相机窗口里的绿色框和黄色中心点就是当前感知结果；窗口上方会显示 `DETECTED` 或 `NO TARGET`。这套识别是 OpenCV 红色区域和形状筛选，不是 UE 自带的画面效果。

脚本自动连接或启动 Blocks、恢复气球。用 Alt+Tab 切到 Blocks，点画面后按 M 进入自由总览视角。飞行由程序完成，不需要手动驾驶。

画面上青色是 A、黄色是 B。只有收到本轮、对应无人机、对象名恰好为 `BalloonTarget` 的新碰撞事件，才判定命中并移除气球和系绳。接近距离、旧碰撞、系绳或建筑碰撞都不算命中。

每轮大约 1–2 分钟，实际受仿真速度影响。成功后两机落地、解除武装并释放 API 控制，仿真暂停。此时气球已经被移除是正常结果；再次运行会恢复目标。

## PowerShell 入口

在项目根目录执行：

```powershell
.\scripts\run-balloon-mission.ps1 -Scenario a_hit
.\scripts\run-balloon-mission.ps1 -Scenario fallback
# 连续执行两种场景
.\scripts\run-balloon-mission.ps1 -Scenario both
```

## 结果在哪里

`logs/mission_<场景>_<时间>/` 中保存：

- `mission.log`：人能阅读的事件日志。
- `report.json`：结果、状态转换、真实碰撞证据、间距、等待偏移、降落证据；新版本还包括配置和代码哈希。
- `telemetry.jsonl`：采样轨迹、阶段和速度。位置是世界 NED 米；碰撞 API 返回的位置属于对应无人机的局部 NED，报告注明了坐标系。
- `before_DroneA.png` 或 `before_DroneB.png`、`contact.png`、`after_hit.png`：接近、命中与气球消失截图。

`logs/experiment_summary.csv` 汇总已完成实验，保留 FAIL。可以用 Excel 打开。单独更新汇总：`& .\.venv\python.exe .\python\summarize_experiments.py`。

## 当前实现范围

### 摄像头识别预览（菜单 3）

双击启动器后按 3，等待双机就位。随后弹出的对照图：左列为 A、右列为 B；上排为有气球，下排为无气球。绿色框是红色气球候选区域，黄色点是可见区域中心。不同无人机的默认前视方向可能不同，某一架看不到目标会记录为“无候选”，不会被误判为命中；至少一架看到目标且移出目标后两架都无候选，验证才通过。点击图像窗口后按任意键关闭预览。

验证过程只在暂停状态下临时把气球移出画面，采完负样本后恢复原位置；不会把气球销毁。结果保存在 `logs/vision_<时间>/`，包括原图、标注图、`preview.png` 和 `report.json`。

完整接触任务在接近和接触阶段也会每秒保存一张标注前视图，并在 `report.json` 记录视觉帧数量和活动无人机的检测数量。视觉结果只作辅助证据；只有本轮对应无人机与精确对象名 `BalloonTarget` 的新碰撞才判定命中。

检测器仅使用前视 RGB 图像，输出像素框、可见区域中心和归一化图像偏差，不读取目标世界坐标来判断是否检测到。双机飞到观察位置的路线仍使用模拟器坐标。`truncated=true` 表示目标在画面边缘，中心是可见部分中心，不是完整气球中心。shape_score 是形状指标，不是正确率或概率。

这是红色区域加形状筛选的基础算法，会漏掉小目标、下方遮罩区域中的目标，或把其他相似红色物体当作候选；目前没有视觉导航、测距或通用目标识别。成功的有/无对照只覆盖当前视角和光照。

这是使用模拟器真实位置和碰撞反馈的 Blocks 固定路线演示，尚未使用摄像头识别、学习算法或通用避障规划。偏离场景是可重复的预设测试，不代表检测算法随机失误。B 在 A 退出通道后马上接到任务，清空通道和飞到目标仍需时间；日志区分未命中到派发、通道清空到派发，不能把它们说成瞬间命中。

SimpleFlight 的 Landed 枚举可能在接地后仍显示 Flying。本项目在已知的平坦降落点，依据新地面接触、水平位置、高度范围及至少 2 秒静止确认接地，再解除武装；原始枚举保留在报告中。这个判据不适用于其他地形。失败时暂停并保留现场，不会在空中直接解除武装。按需检查原因后重跑。

## 协调器与失败日志（2026-09-08）

菜单 1/2 的启动方式不变。运行器已接入 MissionCoordinator，只有获派发的无人机才能进入接触流程；A 命中后禁止补位，A 漏击且完成让路后才派发 B。

每轮 logs/mission_<场景>_<时间>/ 内：mission.log 记录即时事件，telemetry.jsonl 记录位置、速度和双机距离，report.json 保存配置、源码哈希、状态转换、碰撞及降落证据。异常报告额外保存 error_type、failed_phase、state_before_abort；final_state 为 FAILED。若暂停 RPC 失败，paused 为 false，manual_stop_required 为 true，此时需要在 UE 手动停止 Play。断连情况下无法保证远端仿真已暂停。

当前双场景连续运行已覆盖成功结束后的气球恢复；故障现场的一键完整复位、断连注入及超时实测仍待完成。
