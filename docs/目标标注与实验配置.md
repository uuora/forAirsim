# 第 3、4 项：目标登记、仿真标注与实验配置

## 使用

双击 `D:\forAirsim\Capture-Maritime-Experiments.cmd`，依次运行四组配置，每组采集 10 对机载图像。每组结束恢复基础场景。窗口关闭或接口失败时，本轮报错并保留 manifest；进程被强行终止可能无法恢复，此时重启海事场景即可恢复保存的基础地图。此入口只操作环境参数和静态物体摆放，不执行飞行任务。

单组命令：

```powershell
.venv\python.exe python\capture_dual_cameras.py --pairs 10 --ground-truth --scenario baseline
```

scenario 可选 baseline、low_sun、raised_waves、occlusion。普通 `Capture-Dual-Cameras.cmd` 继续只采集图像和位姿，不导出真值。

## 第 3 项：稳定编号

`configs/maritime_targets.json` 是编号的权威来源：

| 编号 | 类别 | 属性 |
|---|---|---|
| vessel_001 | vessel，类别 0 | 七个船体部件组成的一个目标 |
| balloon_001 | balloon，类别 1 | 红色 |
| balloon_002 | balloon，类别 1 | 黄色 |
| balloon_003 | balloon，类别 1 | 红色 |

Unreal 重建可能改变 Actor 名称后缀。登记器按约束匹配并检查部件数量，保存本轮实际名称映射；不会依据临时后缀改变目标编号。字符串和平台不属于目标类别。

真值位于每次采集目录的 `evaluation_ground_truth/`：

- registry.json：目标登记与运行时名称映射。
- annotations.jsonl：原始图像路径、pair_id、车辆、图像时间戳、查询时间、目标编号、类别、目标部件全局 NED 位置及返回的 2D 框。
- DroneA_review.jpg / DroneB_review.jpg：首对图像的待复核标注预览。

位置来自仿真对象 API，坐标系是全局 NED；它与机载相机的车辆局部 NED 不同，不能直接混用。真值仅供评估或人工复核标注，不是感知模型输出。

## 标注质量边界

AirSim 检测接口根据部件投影包围盒与可见性检查返回结果。船框是返回部件框的并集，不是完整船体轮廓，也不是可见像素掩膜；在停机位遮挡下可能漏掉桅杆等部件，或包含被甲板遮住的区域。本机预览已观察到这些现象。

没有返回框的目标标为 not_returned_visibility_unknown，仍保留其登记和位置，不能把“没有返回”解释为“不存在”。图像和标注通过不同 RPC 查询，适用本轮静态目标配置；尚未保证动态目标逐像素同步。原始 PNG 保持不变，所有标注带 REQUIRES_REVIEW_BEFORE_TRAINING。当前没有生成可直接投入 YOLO 训练的 labels，也没有制造空标签背景图。

## 第 4 项：实验配置

`configs/maritime_experiments.json` 保存以下参数：

| 配置 | 光照 | 波浪位移绝对值上界 | 黄色气球 |
|---|---|---|---|
| baseline | 原始太阳方向 | 0.43 米 | 原位 |
| low_sun | 低角度太阳、改变方位 | 0.43 米 | 原位 |
| raised_waves | 原始太阳方向 | 0.645 米 | 原位 |
| occlusion | 原始太阳方向 | 0.43 米 | 移到船后方 |

这是视觉扰动配置，不是正式海况等级。增强波浪情况下，平台底部距公式允许最高波峰仍有 2.6−0.645=1.955 米净空。无浮力或风场扰动实验。

每次显式应用全部参数，读取并验证太阳方向和目标位置；波浪材质切换检查 API 返回值。材质没有运行时读回接口，因此材质证据限于 API 确认、资产哈希和实际画面。每个目录保存 experiment.json、配置副本和相关代码/地图/材质 SHA-256。四组批处理会检查图像哈希、尺寸、标注关联、目标编号和框范围，生成 `logs/maritime_experiments_时间.json`。

配置中 seed=20260915 是为后续采样预留的值：本轮配置没有随机抽样，也没有控制 Unreal 渲染或波浪时间。当前保证参数可重复，不保证逐像素复现。保持配置不变重采，也不构成独立场景数据集；划分训练/验证/测试时必须按采集会话与场景条件分组。
